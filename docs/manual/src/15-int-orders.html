Tutorial: orders in from a partner

A retailer, PartnerA, sends you X12 850 purchase orders. In this tutorial you build the complete inbound flow the way it runs in production: Bots fetches the orders, checks them, sends a 997 acknowledgement back, and delivers every order twice to your ERP, as a csv file and as rows in two database tables. It takes about two hours. Do Tutorial: your first route and Tutorial: your first translation first.

In plain words

PartnerA puts order files on its server. Bots picks them up, reads each order in the file, and checks it. It tells PartnerA "received" with a small 997 file. Each good order goes to your ERP: once as a spreadsheet-like csv file and once straight into the ERP database. A bad order is stopped and shown as an error, and the good orders in the same file still go through.

What you will build

MyCompany sells office supplies to PartnerA, a retailer. PartnerA sends purchase orders as X12 850 (version 004010) files, several orders in one file. PartnerA also has a test system that sends test orders with another ID, PARTNERATEST. Your ERP wants each order as a csv file in a folder (production and test orders in separate folders) and also as rows in its tables edi_orders (one row per order) and edi_order_lines (one row per order line). PartnerA wants a 997 for every file.

  1. The channel partnera_sftp_in fetches the files. In this tutorial it is a file channel on a folder; for real use you change it to SFTP (Part 5 shows the settings).
  2. The route orders_in reads each file as an X12 interchange. Bots checks the envelope (ISA/GS/ST and their counts), finds the sender (PARTNERA or PARTNERATEST) and the test indicator (ISA15), and splits the file into orders.
  3. For each order the translation runs the mapping orders_x12_to_db. It checks the order, stops duplicates and builds a Python object for the database. It then asks Bots for a second translation of the same order (a chained translation with alt csv), which runs orders_x12_to_csv and makes the csv file.
  4. Because of a confirm rule, Bots makes a 997 for each functional group (GS) of the file.
  5. Four route parts deliver the results: the database object to erp_db_out, production csv files to erp_orders_out, test csv files to erp_orders_test_out, the 997 to partnera_sftp_out.
  6. The communication script of erp_db_out inserts the order header and its lines in one database transaction.

What you need

  • Bots 4.0.0 installed, with an environment you can use for this tutorial (see Environments). This tutorial was checked with Bots 4.0.0 on Windows with SQLite; every input and output below is copied from those runs.
  • The pages X12, Database channels, Translations and Acknowledgements as reference.
  • For the database: SQLite needs nothing extra. For MySQL/MariaDB or PostgreSQL install the driver (see Database channels).
  • The specification of your partner: its ISA and GS IDs and qualifiers for production and test, the version (here 004010), and which segments it sends. See Planning an integration.

Part 1: The environment and the ERP database

  1. Make or choose an environment for the tutorial, for example C:\edi\tutorial or /srv/edi/tutorial, with bots-init (see Environments). All paths below are relative to that folder.
  2. Turn on control numbers per partner. In config/bots.ini, section [settings], set: 
    interchangecontrolperpartner = True
    With this setting the ISA13 control number of the files you send counts per sender and receiver: PartnerA and its test system each get their own row of numbers, starting at 1. Without it there is one counter per sender (MyCompany) for all partners. Decide this before the first file is sent; see Counters for what happens to the numbers when you change it later.

Part 2: The grammars

A grammar describes a file format. You need four. Bots 4.0 itself comes without X12 message grammars; the grammars of this tutorial are cut down to the segments that PartnerA sends and that you write, so that you can read them in full. They are correct for version 004010 as far as they go, but a real partner may send segments that are not in them, and Bots then rejects the file. For real partners, install complete X12 grammars from a plugin that contains them (SysTasks → Plugins → Read plugin, see Plugins) and compare them with the implementation guide of the partner.

  1. Write the envelope grammar usersys/grammars/x12/x12.py. Bots reads it for every X12 file: for reading, its QUERIES find the sender (ISA06), the receiver (ISA08), the control number (ISA13) and the test indicator (ISA15); for writing, its syntax gives the defaults for the envelope of every X12 file you send.

    'ISA07': 'ZZ',           # qualifier of the receiver ID (ISA08)

Part 3: Partners and partner settings

Bots knows the sender and receiver of a file by the IDs in ISA06 and ISA08, without the padding spaces. PartnerA sends production orders as PARTNERA and test orders as PARTNERATEST, both to MYCOMPANY, all with qualifier ZZ.

  1. Add the partners. Configuration → Partners → Add: tick Active, Partner identification MYCOMPANY, Name MyCompany, Save. Then PARTNERA (PartnerA) and PARTNERATEST (PartnerA test system).
  2. Write the partner syntax usersys/partners/x12/PARTNERA.py. When Bots writes an X12 file to (or from) this partner, these values override the envelope grammar. Put here what the partner's guide asks for: 
    # Settings for PartnerA (production ID PARTNERA). Used when Bots writes an X12 file to or from this partner.
syntax = {
    'ISA05': 'ZZ',           # qualifier of our ID (MYCOMPANY)
    'ISA07': 'ZZ',           # qualifier of PartnerA's ID
    'version': '00401',      # ISA12 as agreed with PartnerA
    'ISA15': 'P',            # production data
}
  3. Write usersys/partners/x12/PARTNERATEST.py for the test system. The only difference is ISA15 'T', so every file you send to the test ID is marked as test data, also 855s, 856s and 810s from the outbound tutorial: 
    # Settings for the test system of PartnerA (ID PARTNERATEST).
syntax = {
    'ISA05': 'ZZ',
    'ISA07': 'ZZ',
    'version': '00401',
    'ISA15': 'T',            # everything we send to this ID is test data
}
Tip

Many retailers use another ID in GS02/GS03 than in ISA06/ISA08, or a DUNS number with qualifier 01. For that, Bots 4 has the syntax setting IDmode (partner ID ISA-ID|qualifier|GS-ID) and the settings ISA06, ISA08, GS02, GS03 in the partner syntax. See Envelopes. Note that Bots checks confirm rules with GS02/GS03 and sends the 997 to GS02.

Part 4: The mappings and translations

Two mappings read the same 850: one for the database, one for the csv file. The code that reads and checks the order is the same for both, so it is in a separate file that both import.

  1. Write the shared code usersys/mappings/x12/orders_common.py. It reads the order into a plain dict (header and a list of lines) and raises an error for an order the ERP can not use: no ship-to address, or a line without your item number. 
    """Shared code of the two order mappings: read one X12 850 into a plain Python dict.
Not a mapping itself (no translation uses it)."""
from bots.botslib import MappingFormatError


def read_order(inn):
    """Return {'header': {...}, 'lines': [...]} for the 850 in inn; raise an error for a bad order."""
    order_no = inn.get({'BOTSID': 'ST'}, {'BOTSID': 'BEG', 'BEG03': None})
    header = {
        'order_no': order_no,
        'partner': inn.ta_info['frompartner'],
        'ordered_on': inn.get({'BOTSID': 'ST'}, {'BOTSID': 'BEG', 'BEG05': None}),
        'deliver_by': inn.get({'BOTSID': 'ST'}, {'BOTSID': 'DTM', 'DTM01': '002', 'DTM02': None}),
        'buyer_dept': inn.get({'BOTSID': 'ST'}, {'BOTSID': 'REF', 'REF01': 'DP', 'REF02': None}),
        'currency': inn.get({'BOTSID': 'ST'}, {'BOTSID': 'CUR', 'CUR01': 'BY', 'CUR02': None}) or 'USD',
        'test_flag': inn.ta_info['testindicator'],
    }
    # the ship-to address: required by our ERP
    shipto = inn.getloop({'BOTSID': 'ST'}, {'BOTSID': 'N1', 'N101': 'ST'})
    shipto = next(iter(shipto), None)
    if shipto is None:
        raise MappingFormatError('Order "%(order)s" has no ship-to address (N1*ST).', {'order': order_no})
    header.update({
        'recipient_code': shipto.get({'BOTSID': 'N1', 'N104': None}),
        'recipient_name': shipto.get({'BOTSID': 'N1', 'N102': None}),
        'shipto_addr1': shipto.get({'BOTSID': 'N1'}, {'BOTSID': 'N3', 'N301': None}),
        'recipient_city': shipto.get({'BOTSID': 'N1'}, {'BOTSID': 'N4', 'N401': None}),
        'recipient_state': shipto.get({'BOTSID': 'N1'}, {'BOTSID': 'N4', 'N402': None}),
        'shipto_zip': shipto.get({'BOTSID': 'N1'}, {'BOTSID': 'N4', 'N403': None}),
    })
    lines = []
    for count, po1 in enumerate(inn.getloop({'BOTSID': 'ST'}, {'BOTSID': 'PO1'}), start=1):
        vendor_item = po1.get({'BOTSID': 'PO1', 'PO108': 'VP', 'PO109': None})
        if not vendor_item:
            raise MappingFormatError('Order "%(order)s" line %(line)s has no vendor item number (PO108 VP).',
                                     {'order': order_no, 'line': count})
        lines.append({
            'order_no': order_no,
            'partner': header['partner'],
            'line_seq': po1.get({'BOTSID': 'PO1', 'PO101': None}) or str(count),
            'buyer_item': po1.get({'BOTSID': 'PO1', 'PO106': 'BP', 'PO107': None}),
            'vendor_item': vendor_item,
            'upc': po1.get({'BOTSID': 'PO1', 'PO110': 'UP', 'PO111': None}),
            'item_descr': po1.get({'BOTSID': 'PO1'}, {'BOTSID': 'PID', 'PID01': 'F', 'PID05': None}),
            'qty': po1.get({'BOTSID': 'PO1', 'PO102': None}),
            'unit_code': po1.get({'BOTSID': 'PO1', 'PO103': None}),
            'price_each': po1.get({'BOTSID': 'PO1', 'PO104': None}),
        })
    return {'header': header, 'lines': lines}
    • inn.ta_info['frompartner'] is the sender found by the envelope grammar (PARTNERA); inn.ta_info['testindicator'] is ISA15 (P or T).
    • MappingFormatError stops this order only. The text is what you see in Incoming.
  2. Write the database mapping usersys/mappings/x12/orders_x12_to_db.py. For editype db the mapping puts any Python object in out.root; Bots stores it and gives it to the communication script of the database channel. 
    """X12 850 from a retailer -> one Python object for the database channel erp_db_out.
After this mapping Bots runs the translation with alt 'csv' (the ERP csv file) for the same order."""
from bots import transform
from bots.botslib import MappingFormatError
from .orders_common import read_order


def main(inn, out):
    order = read_order(inn)
    header = order['header']
    # botskey: the order number is shown in the reports and can be used in file names
    inn.ta_info['botskey'] = out.ta_info['botskey'] = header['order_no']

    # a retailer sometimes sends the same order twice: stop it here, before the csv and the database
    key = '%(partner)s/%(order_no)s' % header
    seen = transform.persist_lookup('orders_in', key)
    if seen is not None:
        raise MappingFormatError('Order "%(key)s" was already received on %(seen)s.', {'key': key, 'seen': seen})
    transform.persist_add('orders_in', key, transform.strftime('%Y-%m-%d %H:%M'))

    out.root = order          # the communication script erp_db_out.py gets this object
    return 'csv'              # chain: next translation x12 / 850004010 with alt 'csv'
    • Duplicate check: persist_lookup/persist_add remember in the Bots database which orders were received (see persist). A second copy of an order stops here, before the csv file is made. The entries are kept for maxdayspersist days (default 30).
    • Chained translation: return 'csv' tells Bots to translate the same order again with the translation that has Alternative translation csv. If this mapping raises an error, there is no csv file either: the ERP gets the order in both places or in none.
  3. Write the csv mapping usersys/mappings/x12/orders_x12_to_csv.py: 
    """X12 850 from a retailer -> the csv order file for the ERP (one line per order line)."""
from bots import transform
from .orders_common import read_order

HEADER_FIELDS = ('order_no', 'partner', 'recipient_code', 'recipient_name', 'shipto_addr1', 'recipient_city',
                 'recipient_state', 'shipto_zip', 'test_flag')
LINE_FIELDS = ('line_seq', 'buyer_item', 'vendor_item', 'upc', 'item_descr', 'qty', 'unit_code', 'price_each')


def record(values):
    """Bots skips a whole put() if one value is None: leave out the empty values."""
    return {key: value for key, value in values.items() if value not in (None, '')}


def main(inn, out):
    order = read_order(inn)
    header = order['header']
    out.ta_info['botskey'] = header['order_no']
    for line in order['lines']:
        values = {'BOTSID': 'line',
                  'ordered_on': transform.datemask(header['ordered_on'], 'CCYYMMDD', 'CCYY-MM-DD'),
                  'deliver_by': transform.datemask(header['deliver_by'], 'CCYYMMDD', 'CCYY-MM-DD')}
        values.update((field, header[field]) for field in HEADER_FIELDS)
        values.update((field, line[field]) for field in LINE_FIELDS)
        out.putloop({'BOTSID': 'line'}).put(record(values))
    Watch out

    If one value in the dict of a put() is None, Bots skips the whole put() without an error (the debug log says "None" in put …). An order without a delivery date would then lose all its fields. The helper record() leaves out the empty values; use it, or put optional fields in a put() of their own.

    """Database channel erp_db_out: writes one received order into the ERP tables edi_orders and edi_order_lines.
Bots makes the connection (field Database of the channel), calls outcommunicate once per order, commits
when it ends without error and rolls back when it raises an error: an order is written completely or not."""

HEADER_FIELDS = ('order_no', 'partner', 'ordered_on', 'deliver_by', 'buyer_dept', 'currency',
                 'recipient_code', 'recipient_name', 'shipto_addr1', 'recipient_city', 'recipient_state', 'shipto_zip',
                 'test_flag')
LINE_FIELDS = ('order_no', 'partner', 'line_seq', 'buyer_item', 'vendor_item', 'upc', 'item_descr', 'qty',
               'unit_code', 'price_each')


def insert_sql(table, fields):
    return 'INSERT INTO %s (%s) VALUES (%s)' % (
        table, ', '.join(fields), ', '.join('%%(%s)s' % field for field in fields))


def outcommunicate(channeldict, dbconnection, db_object):
    header = db_object['header']
    cursor = dbconnection.cursor()
    cursor.execute('SELECT COUNT(*) AS found FROM edi_orders WHERE partner = %(partner)s AND order_no = %(order_no)s',
                   header)
    if cursor.fetchone()['found']:
        raise Exception('Order %(order_no)s of %(partner)s is already in edi_orders.' % header)
    cursor.execute(insert_sql('edi_orders', HEADER_FIELDS), header)
    for line in db_object['lines']:
        cursor.execute(insert_sql('edi_order_lines', LINE_FIELDS), line)
    • The script does not commit. Bots commits when outcommunicate ends without error and rolls back when it raises one. The header and the lines of an order are written together or not at all; the other orders are not affected.
    • The placeholders %(name)s work for all databases Bots connects to.
    • The duplicate check in the script is a second safety net, for orders that reach the ERP another way.

Variations

  • Several retailers. Add each retailer as a partner, with its own partner syntax file and its own SFTP channels. Put the retailers in a partner group Retailers and use Topartner tochannel in the route part of the 997 to send each 997 over the right channel. Give a retailer its own translation (Frompartner in the translation) when its 850 differs.
  • A VAN or mailbox instead of the partner's server: the channels change, nothing else.
  • Only the database or only the csv file. Remove the return value 'csv' (no chain) or make orders_x12_to_csv the only translation.
  • Stop the whole file for one bad order. Some partners want all or nothing. Set 'KillWholeFile': True in the syntax of 850004010.py: one error then drops all results of the file.
  • Track the 997s PartnerA sends for your 855s, 856s and 810s: see Acknowledgements and the outbound tutorial.
  • Business checks against the ERP (known items, prices): read them in the mapping with a code list (Code lists) or a query, and raise MappingFormatError with a clear text.
  • Running on a schedule: see Scheduling and Going live.

Tutorial: acknowledgements, ship notices and invoices out

After the orders come in (previous tutorial), your ERP answers: it confirms the orders, ships them and sends the invoice. In this tutorial Bots turns these ERP data into X12 855 order acknowledgements, 856 ship notices and 810 invoices for PartnerA, reads database rows only once, and sends one file per partner and message type per run. It takes about three hours.

In plain words

The ERP writes what it wants to tell PartnerA in its own tables and files: "we accept your order", "the goods left today in these two boxes", "here is the bill". Bots collects that, writes it in the X12 language PartnerA expects, puts all documents of one kind for one partner together in one file with the next control number, and drops it in PartnerA's mailbox. Rows Bots has handled are marked, so nothing is sent twice.

What you will build

One route docs_out with three sources:

  • Order acknowledgements (855). The ERP writes one row per order line in table edi_ack_lines with send_status = 'NEW'. Bots reads the new rows, makes one 855 per order, and marks the rows SENT after a successful translation, or ERROR.
  • Ship notices (856). The ERP writes a shipment in edi_shipments, its cartons in edi_packages (with the carton label number and the tracking number of the carrier) and the contents of each carton in edi_package_lines. Bots makes one 856 per shipment with the hierarchy shipment, order, carton, item.
  • Invoices (810). The ERP writes one XML file per invoice in a folder. Bots checks the totals and makes an 810 with three addresses, a freight charge and a discount.

All results for one partner and one message type in a run go in one interchange, with the next control number of that partner, in a file named after partner, message type and control number.

What you need

  • The environment of Tutorial: orders in from a partner, after its run: the partners, the envelope grammar x12.py, the partner syntax files, the channel partnera_sftp_out, interchangecontrolperpartner = True, and the ERP database with the orders PA-778201, PA-778202 and TST-0001.
  • Reference: Database channels, Route scripts, XML and JSON, Code lists, Envelopes, Counters.

import itertools

SELECT_NEW = """
    SELECT a.partner, a.order_no, a.line_seq, a.ack_code, a.qty, a.unit_code, a.price_each, a.promise_date,

def incommunicate(channeldict, dbconnection):
    cursor = dbconnection.cursor()
    cursor.execute(SELECT_NEW, {'status': 'NEW'})
    rows = [dict(row) for row in cursor.fetchall()]     # plain dicts: Bots stores them with pickle
    acks = []
    for (partner, order_no), lines in itertools.groupby(rows, key=lambda row: (row['partner'], row['order_no'])):
        acks.append({'partner': partner, 'order_no': order_no, 'lines': list(lines)})
    return acks                                         # a list: each order becomes one message


def mark_rows(dbconnection, db_object, error):
    """Called by the route script: error is None (translated) or the error text."""
    cursor = dbconnection.cursor()
    for line in db_object['lines']:

               WHERE partner = %(partner)s AND order_no = %(order_no)s AND line_seq = %(line_seq)s

Part 4: Mark the rows after the translation (commit or rollback)

The database channel reads the rows before the translation; whether the translation works is known only after it. A route script with the hook posttranslation runs at that moment. It looks up, for every message received from a database channel in this run, whether its translation ended in an error, and calls mark_rows of that channel's script.

  1. Write usersys/routescripts/docs_out.py (the name is the route ID): 
    """Route script of route docs_out.
After the translation, mark the ERP rows of every message received from a database channel:
SENT when it was translated, ERROR when the translation failed. All in one database transaction per channel:
commit when all rows are marked, rollback when something goes wrong (the rows stay NEW and are read again)."""
from bots import botsglobal, botslib, dbconnect, transform


def translation_error(idta_filein):
    """None if the received message was translated, else the error text."""
    for parsed in botslib.query("""SELECT idta, statust, errortext FROM ta
                                   WHERE parent = %(idta)s AND status = %(status)s""",
                                {'idta': idta_filein, 'status': transform.PARSED}):
        if parsed['statust'] == transform.ERROR:
            return parsed['errortext']
        for message in botslib.query("""SELECT statust, errortext FROM ta
                                        WHERE parent = %(idta)s AND status = %(status)s""",
                                     {'idta': parsed['idta'], 'status': transform.SPLITUP}):
            if message['statust'] == transform.ERROR:
                return message['errortext']
        return None
    return 'not translated'


def posttranslation(routedict):
    # the messages from database channels in this run of the route, per channel
    per_channel = {}
    for row in botslib.query("""SELECT idta, fromchannel, filename FROM ta
                                WHERE idta > %(rootidta)s AND status = %(status)s AND idroute = %(idroute)s
                                AND editype = 'db'""",
                             {'rootidta': botsglobal.currentrun.get_minta4query_route(),
                              'status': transform.FILEIN, 'idroute': routedict['idroute']}):
        per_channel.setdefault(row['fromchannel'], []).append(row)

    for idchannel, rows in per_channel.items():
        channeldict = dict(next(iter(botslib.query('SELECT * FROM channel WHERE idchannel = %(idchannel)s',
                                                   {'idchannel': idchannel}))))
        script, _scriptname = botslib.botsimport('communicationscripts', idchannel)
        dbconnection = dbconnect.connect_channel(channeldict)
        try:
            for row in rows:
                db_object = botslib.readdata_pickled(row['filename'])
                script.mark_rows(dbconnection, db_object, translation_error(row['idta']))
            dbconnection.commit()
        except Exception:
            dbconnection.rollback()
            raise
        finally:
            dbconnection.close()
    • Each received message has a row in the Bots table ta with status FILEIN; its translation makes a child row (PARSED) and a grandchild per message (SPLITUP) with statust ERROR when the mapping failed.
    • The script opens its own connection with the settings of the channel (dbconnect.connect_channel), marks all rows of a channel and commits once. If anything fails, it rolls back: the rows stay NEW and are read in the next run, and the error shows in All runs → Process Errors.
    • The rows are marked when the X12 message is made, not when the file has reached PartnerA. If sending fails, the file stays in Outgoing with an error and you resend it from there; it is not made again from the database.
Watch out

If the engine stops between the translation and posttranslation (a crash, a killed process), the rows stay NEW and the next run makes the 855 again. After such a stop, check whether PartnerA got documents twice.

class HLCounter:
    """Hands out the HL numbers: HL01 is the number of the level, HL02 the number of its parent."""

    def __init__(self, out):
        self.out = out
        self.number = 0

    def add(self, level, parent=None, has_children=True):

        hl = self.out.putloop({'BOTSID': 'ST'}, {'BOTSID': 'HL'})
        hl.put(record({'BOTSID': 'HL', 'HL01': self.number, 'HL02': parent, 'HL03': level,
                       'HL04': '1' if has_children else '0'}))
        return hl, self.number

    """Invoice file of the ERP (xml, grammar invoice_erp) -> X12 810."""
import datetime
import decimal

from bots import transform
from bots.botslib import MappingFormatError

TERMS_DAYS = {'NET30': 30, 'NET45': 45, 'NET60': 60}
# the N1 loops, always in this order: bill to, ship to, remit to
PARTIES = (('BT', 'BillTo'), ('ST', 'ShipTo'), ('RE', 'RemitTo'))
LINES = ({'BOTSID': 'InvoiceDoc'}, {'BOTSID': 'InvLines'}, {'BOTSID': 'InvLine'})


def record(values):
    """Bots skips a whole put() if one value is None: leave out the empty values."""
    return {key: value for key, value in values.items() if value not in (None, '')}


def header(inn, field):
    """Value of a field of InvHeader."""
    return inn.get({'BOTSID': 'InvoiceDoc'}, {'BOTSID': 'InvHeader', field: None})


def amount(inn, field):
    """Amount of a field of InvTotals as a decimal number (0 if empty)."""
    return decimal.Decimal(inn.get({'BOTSID': 'InvoiceDoc'}, {'BOTSID': 'InvTotals', field: None}) or '0')


def us_date(value):
    """MM/DD/YYYY (ERP) -> YYYYMMDD (X12)."""
    return transform.datemask(value, 'MM/DD/CCYY', 'CCYYMMDD')


def main(inn, out):
    inv_number = header(inn, 'InvNumber')
    inn.ta_info['botskey'] = out.ta_info['botskey'] = inv_number
    # the customer number of the ERP gives the partner (code list customer2partner)
    out.ta_info['frompartner'] = 'MYCOMPANY'
    out.ta_info['topartner'] = transform.ccode('customer2partner', header(inn, 'CustRef'))

    # check the totals before anything is sent
    lines_amount = amount(inn, 'LinesAmount')
    total = amount(inn, 'TotalAmt')
    sum_lines = sum(decimal.Decimal(line.get({'BOTSID': 'InvLine', 'Qty': None})) *
                    decimal.Decimal(line.get({'BOTSID': 'InvLine', 'Price': None}))
                    for line in inn.getloop(*LINES))
    if sum_lines != lines_amount:
        raise MappingFormatError('Invoice "%(nr)s": lines add up to %(sum)s, LinesAmount is %(amount)s.',
                                 {'nr': inv_number, 'sum': sum_lines, 'amount': lines_amount})
    if lines_amount + amount(inn, 'FreightAmt') - amount(inn, 'Discount') + amount(inn, 'TaxAmt') != total:
        raise MappingFormatError('Invoice "%(nr)s": Total %(total)s does not match the amounts.',
                                 {'nr': inv_number, 'total': total})

    reference = out.ta_info['reference'].zfill(4)     # ST02 has at least 4 digits
    out.put({'BOTSID': 'ST', 'ST01': '810', 'ST02': reference})
    invoiced_on = us_date(header(inn, 'InvDate'))
    out.put({'BOTSID': 'ST'}, record({'BOTSID': 'BIG', 'BIG01': invoiced_on, 'BIG02': inv_number,
                                      'BIG03': us_date(header(inn, 'PoDate')), 'BIG04': header(inn, 'CustomerPO'),
                                      'BIG07': 'CR' if total < 0 else 'DI'}))
    out.put({'BOTSID': 'ST'}, {'BOTSID': 'CUR', 'CUR01': 'SE', 'CUR02': header(inn, 'Currency') or 'USD'})

    # addresses: one N1 loop per address, in the fixed order of PARTIES
    for qualifier, element in PARTIES:
        party = next(iter(inn.getloop({'BOTSID': 'InvoiceDoc'}, {'BOTSID': 'InvHeader'}, {'BOTSID': element})), None)
        if party is None:
            continue

        def field(name):
            return party.get({'BOTSID': element, name: None})

        n1 = out.putloop({'BOTSID': 'ST'}, {'BOTSID': 'N1'})
        n1.put(record({'BOTSID': 'N1', 'N101': qualifier, 'N102': field('Name')}))
        if field('LocationCode'):
            n1.put({'BOTSID': 'N1', 'N103': '92', 'N104': field('LocationCode')})
        street = (field('Street') or '').splitlines()      # the ERP may give 2 lines: N301 and N302
        if street:
            n1.put({'BOTSID': 'N1'}, record({'BOTSID': 'N3', 'N301': street[0][:55],
                                             'N302': street[1][:55] if len(street) > 1 else None}))
        n1.put({'BOTSID': 'N1'}, record({'BOTSID': 'N4', 'N401': field('City'), 'N402': field('State'),
                                         'N403': field('Zip'), 'N404': field('Country')}))

    days = TERMS_DAYS.get(header(inn, 'PayTerms'))
    if days:
        due = datetime.datetime.strptime(invoiced_on, '%Y%m%d') + datetime.timedelta(days=days)
        out.put({'BOTSID': 'ST'}, {'BOTSID': 'ITD', 'ITD01': '01', 'ITD02': '3',
                                    'ITD06': due.strftime('%Y%m%d'), 'ITD07': days})
    if header(inn, 'ShippedDate'):
        out.put({'BOTSID': 'ST'}, {'BOTSID': 'DTM', 'DTM01': '011', 'DTM02': us_date(header(inn, 'ShippedDate'))})

    for line in inn.getloop(*LINES):
        def value(name):
            return line.get({'BOTSID': 'InvLine', name: None})

        it1 = out.putloop({'BOTSID': 'ST'}, {'BOTSID': 'IT1'})
        it1.put(record({'BOTSID': 'IT1', 'IT101': value('PoLine') or value('LineNo'), 'IT102': value('Qty'),
                        'IT103': value('Uom'), 'IT104': value('Price')}))
        if value('CustItemNo'):
            it1.put({'BOTSID': 'IT1', 'IT106': 'BP', 'IT107': value('CustItemNo')})
        it1.put({'BOTSID': 'IT1', 'IT108': 'VP', 'IT109': value('ItemNo')})
        if value('Upc'):
            it1.put({'BOTSID': 'IT1', 'IT110': 'UP', 'IT111': value('Upc')})
        if value('Descr'):
            it1.put({'BOTSID': 'IT1'}, {'BOTSID': 'PID', 'PID01': 'F', 'PID05': value('Descr')})

    # summary: total (N2: Bots writes 163.03 as 16303), tax, carrier, charges and allowances
    out.put({'BOTSID': 'ST'}, {'BOTSID': 'TDS', 'TDS01': total})
    if amount(inn, 'TaxAmt'):
        out.put({'BOTSID': 'ST'}, {'BOTSID': 'TXI', 'TXI01': 'ST', 'TXI02': amount(inn, 'TaxAmt')})
    if header(inn, 'CarrierScac'):
        out.put({'BOTSID': 'ST'}, record({'BOTSID': 'CAD', 'CAD04': header(inn, 'CarrierScac'),
                                          'CAD07': 'BM', 'CAD08': header(inn, 'BolNo')}))
    if amount(inn, 'FreightAmt'):
        out.putloop({'BOTSID': 'ST'}, {'BOTSID': 'SAC', 'SAC01': 'C', 'SAC02': 'D240',
                                       'SAC05': amount(inn, 'FreightAmt')})
    if amount(inn, 'Discount'):
        out.putloop({'BOTSID': 'ST'}, {'BOTSID': 'SAC', 'SAC01': 'A', 'SAC02': 'C310',
                                       'SAC05': amount(inn, 'Discount')})
    out.put({'BOTSID': 'ST'}, {'BOTSID': 'CTT', 'CTT01': out.getcountoccurrences({'BOTSID': 'ST'}, {'BOTSID': 'IT1'})})
    out.put({'BOTSID': 'ST'}, {'BOTSID': 'SE', 'SE01': out.getcount() + 1, 'SE02': reference})
    • Totals are checked with decimal (not float) before anything is written: the sum of the lines must equal LinesAmount, and lines + freight - discount + tax must equal TotalAmt.
    • Addresses: the N1 loops are written in the fixed order of PARTIES (bill to, ship to, remit to), whatever the order in the XML. A two-line street becomes N301 and N302, each at most 55 characters.
    • Allowances and charges: freight is a charge (SAC*C*D240), the discount an allowance (SAC*A*C310). Ask your partner which codes it wants.
    • Terms: NET30 gives ITD with the net due date (ITD06) and the net days (ITD07).

Variations

  • Several partners. The mappings take the partner from the data, so more retailers need only partners, partner syntax files and channels. To send each partner over its own channel, add route parts with Topartner tochannel (a partner or a partner group such as Retailers). Merging and control numbers already work per partner.
  • One file per document instead of one per partner and type: set 'merge': False in the partner syntax (or in the message grammar).
  • Separate routes per document type (acks_out, asn_out, invoices_out) so they can run at other times. Merging then happens per route; the control numbers stay per partner. Copy the route script for each route.
  • The ERP writes csv instead of XML or tables: only the incoming grammar and the reading part of the mapping change. See csv and fixed.
  • An ERP stored procedure that marks the rows: call it in mark_rows with cursor.execute('CALL …') (MySQL, PostgreSQL) instead of the UPDATE.
  • Process the 997s PartnerA sends back to move the interchanges from Pending to Confirmed: a translation for x12 / 997004010 in the receiving route with the mapping of Acknowledgements.
  • Multiple orders in one shipment: add an O level per order and hang the cartons under the order they belong to (or use the order "pick and pack" structure your partner's guide prescribes).
