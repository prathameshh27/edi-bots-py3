Routes

A route is the work order for a kind of EDI file: where Bots picks the files up, what it does with them, and where it delivers the result. Every file that Bots handles goes through a route, so you set up at least one route before Bots does anything.

In plain words

Think of a route as a conveyor belt. At the start a channel drops files on the belt (from a folder, an FTP server, a mailbox). In the middle Bots can translate each file into another format. At the end another channel takes the files off the belt and delivers them. A route can be one belt, or several belts in a row (route parts) that share the same name.

How it works

A route is a row (or several rows) in Configuration → Routes. Each row is a route part. All parts with the same Idroute form one route; the field Sequence (seq) gives their order. The combination of idroute and sequence must be unique.

When the engine (bots-engine) runs a route part, it does these steps, in this order (bots/router.py):

  1. Route script, function main. If usersys/routescripts/<idroute>.py has a function main, Bots runs only that function for this part and nothing else. See Route scripts.
  2. Check. A part without route script, without incoming channel, without outgoing channel and with Translate set to Nothing is an error: Route "…" is empty: no routescript, not enough parameters.
  3. Receive. If the part has an Incoming channel, Bots runs that channel (only in a normal run, see below). Each received file gets the values of the route: editype, messagetype, frompartner, topartner and alt (only the values that are filled in).
  4. Unzip (if Incoming zip-file handling is set).
  5. Mailbag. If Fromeditype is mailbag, edifact, x12 or tradacoms, Bots splits each file into its separate interchanges and finds the real editype of each (see Preprocessing). With compatibility_mailbag = True in bots.ini only mailbag does this.
  6. Translate (Translate = Translate or Parse & Pass-through): every received file of this route that is not yet translated is parsed, split into messages and translated with the translation that matches; then the results are merged into envelopes. With Pass-through the files are marked as ready to send without any change. With Nothing nothing happens to the files in this part.
  7. Select for the outgoing channel. If the part has an Outgoing channel, Bots gives that channel all files of this route that are ready to send and that pass the filters of the part (Toeditype, Tomessagetype, Testindicator, Frompartner tochannel, Topartner tochannel). A file that is given to a channel is no longer available to later parts.
  8. Ask for acknowledgements (by the confirm rules) and zip (if Outgoing zip-file handling is set; only files of this route part).
  9. Send. Unless Defer is ticked, Bots runs the outgoing channel now. It sends every file of this run that waits for this channel, including files that earlier, deferred parts selected for it.

Files stay in their route: the translation of a part only picks up files received by the same route in the same run, and a part only sends files of its own route.

Which routes run

  • A normal run (bots-engine or bots-engine --new, or the menu Run → Run (only new)): all routes that are active and not marked Not in default run.
  • Routes named on the command line (bots-engine orders_in invoices_out): only these routes, also when they are marked Not in default run. They still must be active.
  • Other runs (--resend, --rereceive, --automaticretrycommunication): all active routes, including those not in the default run, unless you name routes. In these runs incoming channels are not run: no new files are received.

Routes run one after another, sorted by idroute in character order (uppercase before lowercase, digits before letters). Within a route the parts run by sequence. changed in 4.0 The order no longer depends on the database: on every database it is the order SQLite and Bots 3 gave.

Tip

Because routes run in name order, you can give names that put them in the order you want, for example a_orders_in before b_invoices_out. Or name the routes on the command line in the order you want them.

How to make a route with a translation

Example: PartnerA puts X12 850 orders in a folder; you want them as csv in another folder. The translation (grammar, mapping) must exist; see the tutorial.

  1. Make the incoming channel. Configuration → Channels → In → Add incoming channel: Idchannel local_orders_in, Type file, Path botssys/infile/orders, Filename *.edi. Save. See File channels.
  2. Make the outgoing channel. Channels → Out → Add outgoing channel: Idchannel erp_orders_out, Type file, Path botssys/outfile/orders, Filename order_*.csv. Save.
  3. Open a new route. Configuration → Routes → Add.
  4. Tick Active. The engine only uses active routes.
  5. Fill in the name. Idroute orders_in, Sequence 1.
  6. Choose the incoming channel local_orders_in.
  7. Set what comes in. Fromeditype x12, Frommessagetype x12. For X12 and EDIFACT the messagetype is the editype itself: Bots finds the real message type (850, ORDERS…) in the file.
  8. Leave Translate on Translate.
  9. Choose the outgoing channel erp_orders_out.
  10. Save. The list of routes shows orders_in 1. The translate column shows an icon that links to the matching translations.
  11. Test. Put an 850 file in botssys/infile/orders and choose Run → Run (only new). In Incoming you see the file with status Done; the csv file is in botssys/outfile/orders.

How to make a pass-through route

A pass-through route moves files without changing them, for example from an SFTP server of PartnerC to a local folder.

  1. Make the two channels, for example partnerc_sftp_in (type sftp) and local_docs_out (type file).
  2. Add a route: Configuration → Routes → Add; tick Active; Idroute docs_in, Sequence 1.
  3. Choose the incoming channel partnerc_sftp_in.
  4. Set Translate to Pass-through. Fromeditype and frommessagetype may stay empty. The field Alternative translation disappears and is cleared (it has no use here).
  5. Choose the outgoing channel local_docs_out. Use the filename {infile} in that channel to keep the original file names (see file names).
  6. Save and run. The files arrive unchanged.
Note

If you give a pass-through route the editype edifact, x12 or tradacoms, the mailbag step still splits files with several interchanges into one file per interchange. Leave Fromeditype empty to keep files whole.

How to send to a different channel per partner

Example: invoices from your ERP go to PartnerA by SFTP and to PartnerB by FTP. You make one route with three parts: one that receives and translates, and one per partner that sends.

  1. Make part 1. Idroute invoices_out, Sequence 1, Active; Incoming channel erp_invoices_in; Fromeditype csv, Frommessagetype invoices_erp; Translate Translate; Outgoing channel partnera_sftp_out; in Filtering for outchannel set Topartner tochannel to PARTNERA. Save.
  2. Make part 2. Use Save as new on part 1, or add a new route: Idroute invoices_out, Sequence 2, Active; no incoming channel; Translate Nothing; Outgoing channel partnerb_ftp_out; Topartner tochannel PARTNERB. Save.
  3. Optional: a part for all others. Sequence 3, Translate Nothing, an outgoing channel without filter. It gets every file that parts 1 and 2 did not take.
  4. Run and check Outgoing: each invoice shows the channel it went to.
Tip

Topartner tochannel and Frompartner tochannel accept a partner group too. With the group Retailers one part serves all partners in that group. See Partners.

Watch out

A file that no part selects is not sent. It stays with status Stuck and the run report counts it as "files got stuck". Add a last part without filter, or a part to a trash channel (see Other channel types), if some files are not to be sent anywhere.

How to make a route that only runs when you start it

  1. Open the route in Configuration → Routes.
  2. Tick Not in default run and keep Active ticked. Save. Bots sets the same value on every part of this route.
  3. Start it from the web interface: the menu Run → Run (only new) shows a sub-menu with the routes that are active and not in the default run (setting menu_all_routes = notindefaultrun in [webserver] of bots.ini, the default; True lists all active routes, False none). Choose orders_in.
  4. Or start it from the command line: 
    bots-engine orders_in
    With your own configuration directory: bots-engine -c/srv/edi/env1/config orders_in.
  5. Or schedule it separately, see Scheduling.

How to receive from several places in one route

  1. Make part 1 with the first incoming channel (eg partnera_sftp_in), the editype and messagetype, Translate Nothing, no outgoing channel.
  2. Make part 2 with the second incoming channel (eg mail_in), the same editype and messagetype, Translate Nothing.
  3. Make part 3 without incoming channel, Translate Translate. It translates the files of parts 1 and 2 (a translate step needs no editype when the part has no incoming channel).
  4. Make the sending parts as above.

How to collect files of several routes in one connection

Tick Defer in a part to only select files for its outgoing channel; the channel is not run then. The first later part (of any route in the same run) that has the same outgoing channel without Defer sends all waiting files in one session. Use it to make one FTP or SMTP connection instead of many.

Watch out

If no later part sends the deferred channel, the files are not sent in this run and stay Stuck. In acceptance tests (runacceptancetest) Defer is ignored.

Channels

A channel is one way in or out of Bots: a folder, an FTP or SFTP server, a mailbox, a database, a web address. Routes use channels to receive and send files. This page explains what all channels have in common; the pages after it explain each type.

In plain words

A channel is an address book entry plus a delivery method: "pick up files ending in .edi from this folder" or "upload to this server with this user". You make a channel once and use it in as many routes as you like.

How it works

  1. A channel is incoming (in) or outgoing (out). An incoming channel can only be chosen as Incoming channel of a route, an outgoing one only as Outgoing channel.
  2. The type says how Bots talks to the other side: file, ftp, ftps, ftpis, sftp, pop3, pop3s, pop3apop, imap4, imap4s, smtp, smtps, smtpstarttls, http, https, xmlrpc, mimefile, trash, communicationscript, db and database (old).
  3. Incoming: Bots connects (up to maxconnectiontries times), copies every file that matches into its own storage (botssys/data), deletes it on the other side if Remove is ticked, and disconnects. It stops early after Max seconds. Incoming channels only run in a normal ("new") run.
  4. Outgoing: Bots connects and writes every file that waits for this channel, with a name made from the Filename pattern. A file that fails gets status error and can be sent again (Outgoing → resend, or --automaticretrycommunication).
  5. After the session Bots copies the files to the archive, if Archive path is set.
  6. If usersys/communicationscripts/<idchannel>.py exists, Bots uses it: functions in it change details (file name, mail subject, archive path…), and a class with the name of the type (eg class sftp) replaces the built-in one. See Communication scripts.

How to add a channel

  1. Open the form. Configuration → Channels → In → Add incoming channel (or Out → Add outgoing channel).
  2. Type the Idchannel, a short name without spaces, eg partnera_sftp_in. It is also the name of the communication script, if you write one.
  3. Choose In/out and Type. The field Remove shows only for incoming channels and for type communicationscript.
  4. Fill in the fields of that type: see the type pages (file, FTP, SFTP, mail, database, other). The folded blocks Email specific, FTP specific, Database specific, Safe writing & file locking and Other open with a click.
  5. Save. The list shows the channel with its type; the column Routes links to the routes that use it, or offers to add one.
Tip

To make a similar channel (eg the outgoing twin of an incoming one), open the channel, change Idchannel and press Save as new.

Stop

Deleting a channel also deletes its mail addresses per partner and the confirm rules for that channel, and empties the channel field of every route that used it. Check the Routes column first.

A communication script can change the result with a function filename(channeldict, filename, ta) that returns the name to use. Do not change out.ta_info['filename'] in a mapping for this: that is Bots' internal storage name.

Safe writing and locking

Another program must not read a file while Bots still writes it, and Bots must not read a file another program still writes. Three fields help (block Safe writing & file locking):

  • Tmp-part file name (database field mdnchannel; outgoing file, ftp, ftps, ftpis, sftp): Bots writes the file, then renames it, removing the last occurrence of this text. With Filename order_*.csv.tmp and Tmp-part .tmp the file is written as order_17.csv.tmp and renamed to order_17.csv. The other program must ignore *.tmp.
  • System locks (syslock; file and mimefile): Bots locks the file with the operating system while it reads (shared lock) or writes (exclusive lock). Linux: fcntl.lockf, non-blocking: a locked file is an error and is tried again next run. Windows: msvcrt.locking, which retries once a second, 10 times.
  • Lock-file (lockname; file and mimefile): a directory lock. Before reading or writing, Bots creates this file in the channel path; if it already exists, the connection fails (another program has the folder). Bots deletes it at the end. The other program must do the same.
Watch out

The lock file is in the same folder as the files. Make sure the Filename pattern of an incoming channel does not match it: with * Bots would receive its own lock file.

Archive

With Archive path set (eg C:/edi/archive/partnera_sftp_in or /srv/edi/archive/partnera_sftp_in) Bots copies every file the channel received or sent, after the session, to <archive path>/<YYYYMMDD>/. Details:

  • The name in the archive is Bots' internal number. With archiveexternalname = True in bots.ini it is the external name, for types file, ftp, ftps, ftpis, sftp, mimefile and communicationscript with a Filename set. A name that already exists gets _HHMMSS added.
  • With archivezip = True the archive of a day is one zip file YYYYMMDD.zip.
  • The cleanup deletes day folders older than Max days archive (field rsrv3), or else maxdaysarchive of bots.ini (default 180). It deletes everything in the archive path whose name sorts before the cut-off date: use a folder for the archive only.
  • No archive in acceptance tests.
  • Communication script functions archivepath(channeldict) and archivename(channeldict, idta, filename) change folder and name.

Relative paths

Every path in a channel (path, archive path, test path, key and certificate files, SQLite file) that is not absolute is relative to the environment directory: the folder that holds config, botssys and usersys (see Environments). So botssys/infile/orders is inside your environment. Use forward slashes, also on Windows (C:/edi/in). changed in 4.0 In Bots 3 a relative path was relative to the Bots program folder; bots-updatedb lists the channels this concerns.

Test path and acceptance tests

Acceptance test path (testpath) is used in two situations:

  • [acceptance] runacceptancetest = True: a channel with a test path reads from or writes to that folder instead of its real destination. Mail types become mimefile, all others (ftp, sftp, http, db, xmlrpc, communicationscript…) become file; Remove is switched off. A channel without test path keeps working as usual. See Acceptance testing.
  • new in 4.0 [settings] channels_use_testpath = True: the same switch for a test environment, but every channel that would connect to another machine must have a test path, or it is not run (error). Clock and counters run normally.

Certificates (TLS/SSL)

For pop3s, imap4s, smtps, smtpstarttls, ftps, ftpis and https:

  • new in 4.0 Verify server certificate (default on): the certificate of the server must be valid, for the host name of the channel, and issued by a known CA (the CAs of the system, or CA certificate file). Off: any certificate is accepted (as in Bots 3); the connection is encrypted but you do not know with whom. Channels that come from a Bots 3 database are set to off by bots-updatedb.
  • new in 4.0 CA certificate file: PEM file with the CA certificate(s) of the server, or the server's own certificate if it is self-signed.
  • Certificate chain file with Private key file: a client certificate, when the server wants Bots to identify itself. A certificate chain file without key file is used as CA file (as before the CA field existed).

File channels

A channel of type file reads files from a folder or writes files to a folder on the machine where Bots runs, or on a network share it can reach. Use it to exchange files with your ERP system, and for tests.

In plain words

An incoming file channel is an in-tray: Bots takes every file that matches the name pattern. An outgoing file channel is an out-tray: Bots puts each result there under a new name.

How it works

  1. Incoming: Bots lists Path/Filename (wildcards *, ?, […]; only files, not folders), sorted by name, and copies them one by one. With Remove it deletes each file after copying. It stops after Max seconds.
  2. Outgoing: Bots makes the folder if it is missing, makes a name from the Filename pattern, and writes the file. Without {overwrite} it appends to an existing file of the same name. With a Tmp-part it writes first and renames after.
  3. A file that can not be read becomes a process error; the next files go on.

How to receive files from a folder

  1. Open Configuration → Channels → In → Add incoming channel.
  2. Idchannel local_orders_in; Type file.
  3. Tick Remove (in production; leave it off while you test, so you can run the same file again).
  4. Path botssys/infile/orders (inside the environment), or absolute: Windows C:/edi/in, Linux /srv/edi/in.
  5. Filename *.edi. Make sure files that are still being written by the other program do not match (for example the other program writes *.tmp and renames to *.edi).
  6. Optional: Archive path, Max seconds; System locks or Lock-file if the other program uses them.
  7. Save, and use the channel as Incoming channel of a route.

How to write files to a folder

  1. Open Channels → Out → Add outgoing channel.
  2. Idchannel erp_orders_out; Type file.
  3. Path botssys/outfile/orders; Bots makes the folder (and its parents) if it does not exist.
  4. Filename order_{datetime:%Y%m%d}_*.csv (see file names).
  5. Optional: Tmp-part file name .tmp with Filename order_*.csv.tmp, so the ERP system never reads a half-written file.
  6. Save and use it as Outgoing channel of a route. After a run the files are in the folder; in Outgoing each shows its full file name.

FTP and FTPS channels

Types ftp, ftps and ftpis receive files from and send files to an FTP server. ftp is not encrypted; ftps (explicit) and ftpis (implicit) use TLS.

In plain words

FTP is an old, common way to put files on another company's server. Plain FTP sends the password and the files readable for anyone on the way, so use FTPS (or SFTP) when the partner offers it.

How it works

  1. Bots connects to Host and Port, logs in with Username, Password (and Ftp account), and goes to Path, relative to the folder the server shows after login. If that folder does not exist Bots makes it (one level).
  2. ftps (explicit): Bots connects as plain FTP (normally port 21), asks for TLS (AUTH TLS), logs in and protects the data connections (PROT P).
  3. ftpis (implicit): the connection is TLS from the first byte (normally port 990). Bots also sends PBSZ 0 and PROT P and ignores a refusal of these.
  4. Incoming: Bots lists the folder (NLST), keeps the names that match Filename, and downloads them. Folders and empty files are skipped without an error (and are not removed). With Remove the file is deleted on the server after download.
  5. Outgoing: Bots uploads each file with APPE (append) or, with {overwrite} in the Filename, STOR; with a Tmp-part it renames after the upload.
  6. ASCII or binary: without Ftp binary transfer mode Bots uses ASCII mode: when receiving, CRLF line ends become LF and the last line gets a line end; when sending, every line end becomes CRLF. The bytes themselves are not re-coded. Binary mode transfers the file exactly.
  7. Passive or active: passive unless Ftp active mode is ticked. In passive mode Bots opens the data connection (works through most firewalls).
  8. Time-out: ftptimeout in bots.ini (10 seconds).

How to receive from an FTP or FTPS server

  1. Open Configuration → Channels → In → Add incoming channel.
  2. Idchannel partnera_ftp_in; Type ftps (explicit) (or ftp, or ftps (implicit) if the partner says "implicit" or port 990).
  3. Tick Remove (production).
  4. Host ftp.example.com; Port 0 (= 21) for ftp and ftps, 990 for ftpis.
  5. Username and Password as given by the partner.
  6. Path out (the folder where the partner puts your files); empty for the login folder.
  7. Filename *.edi, or * for all.
  8. Open FTP specific: tick Ftp binary transfer mode unless the partner wants ASCII; leave active mode off unless the partner asks for it.
  9. For ftps/ftpis open Other: keep Verify server certificate on; if the server has its own or a private CA, put that certificate in CA certificate file.
  10. Save, add the channel to a route and run. In Incoming the file names show as ftp://out/ORDERS001.edi.

How to send to an FTP or FTPS server

  1. Open Channels → Out → Add outgoing channel; Idchannel partnerb_ftp_out; Type as above.
  2. Host, Port, Username, Password, Path (eg in).
  3. Filename with a unique part, eg INV_{datetime:%Y%m%d}_*.edi. Many servers do not allow append (APPE): then use unique names or {overwrite}.
  4. Optional: Tmp-part .tmp with Filename INV_*.edi.tmp, if the partner picks files up automatically.
  5. FTP specific: binary mode on.
  6. Optional: Max failures (outgoing: number of connection tries).
  7. Save and use it in a route.

SFTP channels

Type sftp receives and sends files over SSH (the SSH File Transfer Protocol). You log in with a password or with a private key. It needs the Python library paramiko (version 2 or higher).

In plain words

SFTP looks like FTP to you, but everything is encrypted, and instead of a password you can use a key file: a long secret that stays on your machine, while the partner only gets the public half.

How it works

  1. Install the library once: pip install bots-ediint[sftp] (part of [bots3] too).
  2. Bots connects to Host and Port and logs in as Username, with one of:
    • password: Password, no key file;
    • key file: Private key file; the Password field is then the passphrase of the key (empty for a key without passphrase), not a login password. Bots reads RSA, ECDSA and Ed25519 keys (and DSA if the installed paramiko still supports it), in OpenSSH or PEM format;
    • a communication script with a function privatekey(channeldict) that returns (key file, key type, passphrase); the type ('RSA', 'ECDSA', 'ED25519', 'DSA') is tried first.
  3. Bots goes to Path (relative to the login folder) and makes it if it is missing.
  4. Incoming: lists the folder, downloads the names that match Filename; with Remove deletes them.
  5. Outgoing: writes each file; a file that already exists is appended to, unless the Filename has {overwrite}; a new file is opened for writing. With a Tmp-part it renames after writing.
  6. SFTP has no ASCII mode: files are transferred exactly.
Watch out

Bots does not check the host key of the server, unless a communication script supplies it with a function hostkey(channeldict) that returns a paramiko key object. This is the same as in Bots 3. Without it, you can not be sure you talk to the right server. See Communication scripts.

How to set up an SFTP channel with a key

  1. Make a key pair (once), for example with OpenSSH: 
    ssh-keygen -t ed25519 -f config/keys/partnera_id_ed25519 -C "MyCompany EDI"
    Windows PowerShell: the same command with ssh-keygen.exe. Give the partner the file ending in .pub. Keep the other file private.
  2. Open Configuration → Channels → In → Add incoming channel.
  3. Idchannel partnera_sftp_in; Type sftp (ssh); tick Remove.
  4. Host sftp.example.net; Port 22 (fill it in: 0 does not work for sftp).
  5. Username as given by the partner. Password: the passphrase of the key, or empty.
  6. Path out; Filename *.xml.
  7. Open Other; Private key file config/keys/partnera_id_ed25519 (relative to the environment, or absolute).
  8. Save and run a route with it. The incoming files show as sftp://home/mycompany/out/….
  9. Make the outgoing twin partnera_sftp_out with Save as new: change In/out to out, Path to in, Filename to eg {messagetype}_*.xml.

With a password instead: leave Private key file empty and type the password in Password.

Mail channels

Bots can receive EDI files as mail attachments (types pop3, pop3s, pop3apop, imap4, imap4s) and send them by mail (smtp, smtps, smtpstarttls). The mail addresses also tell Bots which partner sent a file and to whom a file goes.

In plain words

Bots reads a mailbox like a person would: it opens each mail, checks that the sender is a known partner, saves the attachments as files, and (if you want) deletes the mail. To send, Bots writes a mail with the EDI file attached and hands it to your mail server.

How it works

Receiving

  1. pop3, pop3s, pop3apop: Bots logs in (pop3apop with the APOP method, pop3s over TLS), downloads all mails, and with Remove marks them for deletion; the server deletes them when Bots logs out. If the connection breaks before the logout, Bots forgets the mails it fetched, so they are fetched again next time (no double processing).
  2. imap4, imap4s: Bots opens the mailbox in Path (empty: INBOX) and downloads every mail not marked as deleted. With Remove each mail is deleted directly after download.
  3. For each mail Bots reads the From address and looks for the partner:
    1. the email address per channel of an active partner for this channel (in the partner screen);
    2. else the Mail field of an active partner (several addresses separated by commas);
    3. else the Cc field of an active partner.
    An unknown sender is an error, unless No check from-address is ticked. The same for the To addresses: at least one must belong to a partner (usually your own company), unless No check to-address is ticked. The partners found become frompartner and topartner of the files. Upper and lower case do not matter.
  4. Bots saves each part of the mail with a main content type text or application as a file, except text/html, text/enriched, text/rtf, text/richtext, text/vcard, text/css and application/postscript. So an EDI file in the body of a plain text mail is also received. Empty parts are skipped. A mail without any such part is an error: No valid attachment in received email.
  5. A received MDN (a mail of type multipart/report) is not saved as a file: Bots marks the mail it once sent as confirmed.
  6. If a mail asks for an MDN (header Disposition-Notification-To) and a confirm rule send-email-MDN applies, Bots makes the MDN as an outgoing file (editype email-confirmation) in the same route; an outgoing mail channel in that route sends it.
Tip

For a mailbox that receives EDIFACT, X12 and xml mixed, use Fromeditype mailbag and Frommessagetype mailbag in the route: Bots finds the type of every attachment. See Preprocessing.

Sending

  1. Before connecting, Bots turns each outgoing file into a mail (one file, one mail):
    • From: the mail address of the frompartner of the file: first the email address per channel of that partner for this channel, else its Mail field. So your own company must be a partner with a mail address (eg MYCOMPANY, edi@mycompany.example).
    • To and Cc: the same lookup for the topartner (eg orders@partnera.example).
    • Subject: the internal number of the file (change it with a communication script function subject).
    • The file as attachment named by Filename (default *), or as body, by As body or attachment; encoded by Mime encoding; content type and charset from the grammar of the file.
    • Disposition-Notification-To if a confirm rule ask-email-MDN applies.
  2. Bots connects to the SMTP server (smtps: TLS from the start; smtpstarttls: plain, then STARTTLS), logs in if Username and Password are filled in, and sends the mails to all To and Cc addresses.

How to receive orders from a mailbox

  1. Register the addresses (once): in Configuration → Partners give PARTNERA the Mail orders@partnera.example, and MYCOMPANY the Mail edi@mycompany.example. See Partners.
  2. Open Configuration → Channels → In → Add incoming channel; Idchannel mail_in; Type imap4s (or pop3s).
  3. Tick Remove (otherwise every mail is received again each run).
  4. Host mail.example.org; Port 993 (imap4s; pop3s: 995; imap4: 143; pop3 and pop3apop: 110). The port must be filled in for receiving types.
  5. Username edi@mycompany.example, Password of the mailbox.
  6. imap4 only: Path = the folder, eg INBOX/EDI; empty means INBOX.
  7. Optional, Email specific: tick No check from-address if anyone may send files (then the partner comes from the file itself, or from the route).
  8. Save, and use the channel in a route with Fromeditype/Frommessagetype of the attachments (or mailbag).
  9. Test: send a mail with an attachment from orders@partnera.example; run. In Incoming the mail shows, with the attachment as a file of PARTNERA.

  1. Register the addresses of MYCOMPANY (sender) and of the partner (receiver) as above. To use another address only for this channel, add it in the partner screen under Email address per channel, with this channel.
  2. Open Channels → Out → Add outgoing channel; Idchannel partnera_mail_out; Type smtpstarttls (or smtps, or smtp for a server without TLS).

Database channels

A channel of type db reads data from a database or writes data to it, through a small Python script that you write. new in 4.0 Bots can make the connection for you to MySQL/MariaDB, PostgreSQL, SQLite or Microsoft SQL Server.

In plain words

Instead of files, some systems have the orders in database tables. A database channel runs your query, and each result becomes a "file" for Bots. The mapping then reads the rows directly. For sending, the mapping builds the data and your script writes it into the tables.

How it works

  1. The script is usersys/communicationscripts/<idchannel>.py, eg usersys/communicationscripts/erp_db_in.py. It is required.
  2. Connection. If the field Database (in Database specific) is set and the script has no function connect, Bots connects with Host, Port (0: the standard port: MySQL 3306, PostgreSQL 5432, SQL Server 1433), Username, Password; the database name is Path (for SQLite: the file), or Filename when Path is empty; driver options from Parameters. Otherwise the script's connect(channeldict) returns a connection, and disconnect(channeldict, dbconnection) closes it, as in Bots 3.
  3. Incoming: Bots calls incommunicate(channeldict, dbconnection). What it returns:
    • a list or tuple: every element becomes one received "file" (one message);
    • anything else that is not empty (a dict, an object): one received file;
    • None or empty: nothing received.
    Bots stores each element with Python pickle. In the route, use Fromeditype db and a free messagetype (eg orders_db) that a translation uses; the mapping gets the object as inn.root. No grammar is needed. See Other editypes.
  4. Outgoing: the mapping (toeditype db) puts any Python object in out.root; for each such file Bots calls outcommunicate(channeldict, dbconnection, db_object).
  5. Commit and rollback (connection made by Bots): Bots commits after each incommunicate / outcommunicate that ends without error and rolls back after an error; the file is then in error and can be resent. Do not commit in the script. With your own connect you commit yourself (usually in disconnect, or in the functions).
  6. The connection made by Bots behaves the same for all four databases: cursor.execute(sql, params) with %(name)s and a dict, or %s and a list; rows are dicts that also work by position (row['po'] and row[0]); cursor.fetchone(), fetchall(), fetchmany(), executemany(), rowcount, lastrowid. The driver's own connection is dbconnection.native.

How to read orders from a database

  1. Install the driver for your database in the Python of Bots: MySQL/MariaDB pip install bots-ediint[mysql] (mysqlclient); PostgreSQL pip install bots-ediint[postgresql] (psycopg; psycopg2 also works); SQL Server pip install bots-ediint[mssql] (mssql-python, no ODBC driver needed; or pyodbc with "ODBC Driver 18/17 for SQL Server"); SQLite needs nothing.
  2. Open Configuration → Channels → In → Add incoming channel; Idchannel erp_db_in; Type db.
  3. Host db.example.com; Port 0; Username bots, Password; Path the database name, eg erp.
  4. Open Database specific; Database PostgreSQL.
  5. Optional, Parameters: driver options, eg sslmode=require.
  6. Save.
  7. Write the script usersys/communicationscripts/erp_db_in.py: 
    def incommunicate(channeldict, dbconnection):
    cursor = dbconnection.cursor()
    cursor.execute("SELECT * FROM orders WHERE status = %(status)s", {'status': 'ready'})
    orders = cursor.fetchall()
    cursor.execute("UPDATE orders SET status = 'sent' WHERE status = %(status)s", {'status': 'ready'})
    # one message per order; return [orders] for one message with all rows
    return [dict(order) for order in orders]
  8. Make the route with Incoming channel erp_db_in, Fromeditype db, Frommessagetype orders_db, and a translation db / orders_db with a mapping that reads inn.root['po'] etc.
  9. Run. In Incoming each order shows as a file named after Path.

How to write to a database

  1. Make an outgoing channel of type db, eg erp_db_out, with the same connection fields.
  2. In the mapping (toeditype db), set out.root to the data, eg a list of dicts.
  3. Write the script usersys/communicationscripts/erp_db_out.py: 
    def outcommunicate(channeldict, dbconnection, db_object):
    cursor = dbconnection.cursor()
    for line in db_object:
        cursor.execute(
            "INSERT INTO received_orders (po, qty) VALUES (%(po)s, %(qty)s)", line)
  4. Run. Bots commits per file; an error rolls back that file only.

Other channel types

Besides files, FTP, SFTP, mail and databases, Bots has channel types for special cases: mail as files (mimefile), throwing files away (trash), your own program (communicationscript), web servers (http, https), XML-RPC (xmlrpc), and the old database type.

In plain words

These types fill the gaps: a folder full of saved mails, a bin for files nobody needs, a hook to run your own program, and a way to fetch from or post to a web address.

  2. Fill in the Email specific fields as for a mail channel (checks of addresses for in; Mime encoding and body/attachment for out). Partners need mail addresses.

  1. Add an outgoing channel with Type trash/discard, eg discard_out. No other field is needed.
  2. Use it as the last part of a route, without filter, to catch files that no other part sends (so they do not stay Stuck); or with a filter, eg Tomessagetype for messages you do not need.

changed in 4.0 As in Bots 3.x, a trashed file is registered as sent, with an empty file name; reports count it as handled.

http and https

Needs the library requests: pip install bots-ediint[http].

  • The url is http(s)://<Host>[:<Port>]/<Path> (port 0: no port in the url).
  • With Username and Password Bots uses HTTP basic authentication.
  • Parameters are added as query parameters: key=value, several separated by & (or ;, ,, space); values may be url-quoted (%26 is &) and may contain =. When sending, placeholders such as {botskey} are filled in per file. A leading ? is ignored.
  • Incoming: one GET per run. Status other than 200 is an error. An empty body means nothing to receive.
  • Outgoing: a POST per file with the file as body; headers Content-Type (from the file, with charset), Content-Disposition (attachment if As body or attachment is As attachment, else inline; with filename= from the Filename pattern if one is set). Mime encoding Base64 (or Base64 if not ascii with a non-ascii charset) sends the body Base64-encoded with Content-Transfer-Encoding: base64. A response other than 200 is an error.
  • https: the certificate is verified (Verify server certificate, CA certificate file); Certificate chain file with Private key file is a client certificate. For http no certificates are used.
  • Other headers, parameters and settings: subclass in a communication script (class http or https with headers = {...}, params = {...}).
  1. Add an outgoing channel: Type https, Idchannel partnerc_https_out; Host edi.example.com; Port 0; Path api/inbound; Username/Password if needed.
  2. Optional: Parameters sender=MYCOMPANY&ref={botskey}; Filename {botskey}.xml; Debug level 1 or 2 to log requests and responses.
  3. Save and use it in a route. Outgoing shows the url with the file name.

xmlrpc

  • Bots calls http://<Username><Password>@<Host>:<Port>; the remote function is Path. Note that Bots puts Username and Password together without a separator.
  • Incoming: calls Path() without arguments until it returns None (or an error); each result is written as JSON and received as one file.
  • Outgoing: calls Path(content) with the text of each file; with Debug level set, the response is logged.
  • Only http, no https. XML is read safely (defusedxml).
