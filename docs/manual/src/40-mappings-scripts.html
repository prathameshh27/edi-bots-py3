Mappings

A mapping script is a small Python file that says which data of an incoming message goes where in the outgoing message. Bots reads and checks the files with the grammars; the mapping does the business logic. You need one mapping for every translation.

In plain words

Bots has already read the incoming order into a tree of records. Your mapping is a short recipe: "take the order number from here, put it there; for every line, copy the article and the quantity". Bots then writes the result in the right format and checks it.

How it works

For every message in an incoming file Bots does these steps:

  1. Bots parses the incoming file with the incoming grammar. The result is a tree of nodes: one node per record (segment), each with a dict of fields. If the grammar has nextmessage (EDIFACT, X12) or nextmessageblock (csv, fixed), the file is split into messages and each message gets its own tree.
  2. Bots looks up the translation rule (Configuration → Translations) with the editype, messagetype, partners and alt of the message. The rule names the mapping script and the outgoing editype and messagetype.
  3. Bots imports usersys/mappings/<incoming editype>/<mapping script>.py and calls its function main with two objects: inn (the incoming message) and out (an empty outgoing message).
  4. When main returns, Bots reads the outgoing grammar (and the partner syntax), checks the out tree against it (mandatory fields, lengths, number formats, record counts), and writes the file. Later the file is merged and enveloped (see Envelopes).

Every value in inn and out is a string. A field that is not in the incoming file is not in the tree at all: reading it gives None.

A minimal mapping

File usersys/mappings/x12/orders_x12_to_csv.py, used by a translation from x12 850004010 to csv orders_erp:

from bots import transform


def main(inn, out):
    """X12 850 purchase order to the csv of the ERP system."""
    out.put({'BOTSID': 'HDR',
             'ordernumber': inn.get({'BOTSID': 'ST'}, {'BOTSID': 'BEG', 'BEG03': None}),
             'orderdate': inn.get({'BOTSID': 'ST'}, {'BOTSID': 'BEG', 'BEG05': None}),
             'buyer': inn.ta_info['frompartner']})
    for po1 in inn.getloop({'BOTSID': 'ST'}, {'BOTSID': 'PO1'}):
        line = out.putloop({'BOTSID': 'HDR'}, {'BOTSID': 'LIN'})
        line.put({'BOTSID': 'LIN',
                  'linenumber': po1.get({'BOTSID': 'PO1', 'PO101': None}),
                  'sku': po1.get({'BOTSID': 'PO1', 'PO107': None}),
                  'quantity': po1.get({'BOTSID': 'PO1', 'PO102': None})})

Mpaths: how you point at a field

Every read and write uses an mpath: a series of dicts, one per level of the tree, from the root of the message down to the record you want. Each dict has 'BOTSID' (the record id, for example the segment tag) and can have fields to match. In the last dict, a field with value None means "give me this field".

# the root record UNH, then the child NAD whose 3035 is 'BY'; return its C082.3039
inn.get({'BOTSID': 'UNH'}, {'BOTSID': 'NAD', '3035': 'BY', 'C082.3039': None})
  • Field names are the ids in the grammar. Sub-fields of a composite are written composite.subfield, for example C082.3039.
  • The first dict must match the root record of the message (for EDIFACT UNH, for X12 ST, for csv/fixed the record id of the grammar root).
  • Matching values must be strings: 'BY', not 1.
  • The records and fields are described in Grammar records; use the "view grammar" link in the web interface to see them for your message.

To not write an outgoing message, set out.ta_info['statust'] = transform.DONE before you return. The message is marked as discarded; this is not an error.

When an alt is returned, the translation rule is looked up with that alt. A rule with exactly that alt wins over a rule with an empty alt; if there is none, the rule with an empty alt is used again (so the same mapping runs again, with inn.ta_info['alt'] set).

How errors in a mapping show

  • Any exception in main stops this message. The message gets status error, with a text like ScriptError: Userscript "…/usersys/mappings/x12/orders_x12_to_csv": "KeyError: 'BEG03'". You see it in Incoming and in the run report.
  • The other messages of the same file are still translated (as in Bots 3). To make one error fail the whole file, set syntax 'KillWholeFile': True in the incoming grammar, or raise transform.KillWholeFileException('reason') in the mapping.
  • After main, the outgoing message is checked against its grammar. Errors there (for example [F02] … field "BEG03" is mandatory) are shown the same way.
  • Only the error itself is shown. With debug = True in bots.ini the full Python traceback is shown too; it is always in the log at level DEBUG. changed in 4.0

Other functions Bots calls in a mapping file

  • Acknowledgements. If a translation exists for incoming messagetype 997 (X12) or CONTRL (EDIFACT), Bots uses that mapping to make the acknowledgement: main(inn, out, routedict, ta_fromfile) replaces the built-in mapping, or change(inn, out, routedict, ta_fromfile) runs after the built-in mapping and can change the result. See Acknowledgements.
  • Finding the translation yourself. If usersys/mappings/translation.py has a function gettranslation(idroute, message), Bots calls it when no translation rule is found. It must return a tuple (mapping script, outgoing editype, outgoing messagetype), or (None, None, None).

How to write and connect a mapping

  1. Find the grammars. Note the incoming editype and messagetype (for example x12 850004010) and the outgoing ones (csv orders_erp). Both grammars must exist in usersys/grammars/.
  2. Create the file. Make usersys/mappings/x12/orders_x12_to_csv.py. The folder is the incoming editype. The file name is the name of the mapping; use letters, digits and _ only (a dot in the name means a sub-folder).
  3. Write main. Define def main(inn, out): and fill out with put and putloop, as in the example above.
  4. Add the translation rule. Go to Configuration → Translations → Add. Fill Fromeditype x12, Frommessagetype 850004010, Mapping Script orders_x12_to_csv, Toeditype csv, Tomessagetype orders_erp. Tick Active and save. Leave Alternative translation and the partners empty unless you need different mappings per partner.
  5. Check the script. Run bots-checkusersys -c<config directory>. It imports every script and reports syntax errors.
  6. Run a test file. Put a test file in the folder of the incoming channel and run the route. In Incoming the file should show status OK; in Outgoing you see the result and can open it.

How to debug a mapping

  1. Look at the source as Bots sees it. In Configuration → Translations the name in column Mapping Script is a link that opens the source of the file in usersys; the message types link to their grammar. You need the right to change translations to see these links.
  2. Log values. Write to the Bots log, not to the screen: 
    from bots import botsglobal

def main(inn, out):
    po = inn.get({'BOTSID': 'ST'}, {'BOTSID': 'BEG', 'BEG03': None})
    botsglobal.logger.info('Order %s from %s', po, inn.ta_info['frompartner'])
    print() output only shows on the console of bots-engine when you run it by hand; it is not in the log.
  3. Show the whole tree. Add inn.root.display() (or out.root.display()) in main. Every record is written to the log at level INFO. inn.root.displayqueries() shows the QUERIES values per node.
  4. Check your mpaths against the grammar. Set get_checklevel = 2 in bots.ini during development: every mpath of get, getloop and sort is checked against the grammar, and a wrong record or field name gives Parameter mpath is not valid according to grammar instead of a silent None.
  5. See every record that is read. In bots.ini section [settings] set readrecorddebug = True, log_level = DEBUG and log_file_level = DEBUG. The fields of every incoming record are written to the engine log. Switch it off again; it makes large logs.
    Watch out

    The setting mappingdebug = True sends a trace of every get, getloop, put, change and delete to a separate Python logger named engine.map. In 4.0.0 that logger is not connected to the engine log file, so the trace does not appear there. Log the values you need yourself with botsglobal.logger.info().

  6. Read the log. SysTasks → Logs → Engine logs shows the engine log in the browser.

Mapping functions

This page lists every function you can use in a mapping script: the methods of the inn and out messages and of their nodes, and the helper functions in the module transform. For each one you find the signature, what it returns, an example and the usual mistakes.

In plain words

There are two kinds of tools. The first kind reads and writes the message tree: "get this field", "loop over these lines", "put this value there". The second kind does common jobs: convert a code with a code list, make a unique number, change a date format, remember a value until the next run.

How it works

  1. Message methods are called on inn or out: inn.get(…), out.put(…). They search from the root record of the message.
  2. Node methods are called on a node that getloop or putloop gave you: po1.get(…), line.put(…). They search from that node. The mpath then starts with the record of that node, not with the root of the message.
  3. Transform functions are called as transform.ccode(…) after from bots import transform.

All tree functions take an mpath: dicts from the start record down, each with 'BOTSID'. See Mpaths.

for lin in inn.getloop({'BOTSID': 'UNH'}, {'BOTSID': 'LIN'}):           # message method, from UNH
    article = lin.get({'BOTSID': 'LIN', 'C212.7140': None})               # node method, from this LIN
    qty = lin.get({'BOTSID': 'LIN'}, {'BOTSID': 'QTY', 'C186.6063': '21', 'C186.6060': None})

How to choose the right function

  1. One value: use get. For numbers you calculate with, use getdecimal. To treat 0 as "no value", use getnozero.
  2. Repeating records: loop with getloop; inside the loop use the node's get.
  3. One output record: put. Repeating output records: putloop, then put on the node it returns.
  4. Totals and counts: getcountsum, getcountoccurrences, getcount.
  5. Codes: transform.ccode with a code list; partner data: transform.partnerlookup.
  6. Numbers that must be unique: transform.unique. Memory between runs: transform.persist_*.

get

Signature: inn.get(mpath1, mpath2, …) or node.get(…). Returns: the value (a string) of the one field marked None in the last dict; 1 if the last dict has no None and the record exists (a "does it exist" test); None if nothing matches. When several records match, the first one is used.

po = inn.get({'BOTSID': 'UNH'}, {'BOTSID': 'BGM', 'C106.1004': None})
buyer = inn.get({'BOTSID': 'UNH'}, {'BOTSID': 'NAD', '3035': 'BY', 'C082.3039': None})
if inn.get({'BOTSID': 'UNH'}, {'BOTSID': 'FTX', '4451': 'DEL'}):
    pass   # an FTX with qualifier DEL exists

Common mistakes: two None values in the last dict (Max one "None" in last section); a match value that is not a string; forgetting the root record as first dict; reading a field of a child record without the level in between (QTY is under LIN, so the mpath needs {'BOTSID':'LIN'} before {'BOTSID':'QTY',…}).

getnozero

Signature: getnozero(*mpath). Returns: the value as get does, but None if the value is zero or not a number. Useful for fixed files where empty number fields contain zeros.

discount = inn.getnozero({'BOTSID': 'HDR'}, {'BOTSID': 'LIN', 'discount': None})
if discount:
    lin.put({'BOTSID': 'LIN'}, {'BOTSID': 'ALC', '5463': 'A'})

getdecimal

Signature: getdecimal(*mpath). Returns: a decimal.Decimal. A missing or non-numeric value gives Decimal('0'). A minus sign at the end (12.5-, usual in IDocs) is moved to the front.

qty = po1.getdecimal({'BOTSID': 'PO1', 'PO102': None})
price = po1.getdecimal({'BOTSID': 'PO1', 'PO104': None})
line.put({'BOTSID': 'LIN', 'amount': qty * price})

Common mistakes: it hides errors: a typo in the mpath gives 0, not an error. Mixing with float raises TypeError; use Decimal('1.21').

getrecord

Signature: getrecord(*mpath). All values in the mpath must be strings (no None). Returns: the dict of the record itself (changes to it change the tree), or None.

beg = inn.getrecord({'BOTSID': 'ST'}, {'BOTSID': 'BEG'})
if beg:
    botsglobal.logger.info('BEG has fields %s', sorted(beg))

getloop

Signature: getloop(*mpath). Returns: a generator; each step gives a node that matches the whole mpath. Values in the mpath must be strings; None is not allowed here.

for nad in inn.getloop({'BOTSID': 'UNH'}, {'BOTSID': 'NAD'}):
    qualifier = nad.get({'BOTSID': 'NAD', '3035': None})
    gln = nad.get({'BOTSID': 'NAD', 'C082.3039': None})

For a file that is not split into messages (no root record), inn.getloop searches each top record. Common mistakes: inside the loop, the mpath of the node starts with the node's own record ({'BOTSID':'NAD'}), not with UNH. A generator can be used once; use list(inn.getloop(…)) to loop twice.

getloop_including_mpath

Signature: getloop_including_mpath(*mpath). Returns: for each match a list: the records (dicts) of the levels above, then the node. Bots uses it to split files into messages; you need it when the loop must also know data of the parent.

for *parents, lin in inn.getloop_including_mpath({'BOTSID': 'UNH'}, {'BOTSID': 'LIN'}):
    unh_reference = parents[0]['0062']

getcount

Signature: getcount() (no mpath). Returns: the number of records in the tree (of the message, or below and including the node). Used for segment counts in trailers.

# UNT counts all segments from UNH to UNT; UNT itself is not in the tree yet: + 1
out.put({'BOTSID': 'UNH'}, {'BOTSID': 'UNT', '0074': out.getcount() + 1, '0062': out.ta_info['reference']})

getcountoccurrences

Signature: getcountoccurrences(*mpath). Returns: how many records match (an integer).

nr_lines = inn.getcountoccurrences({'BOTSID': 'ST'}, {'BOTSID': 'PO1'})
out.put({'BOTSID': 'ST'}, {'BOTSID': 'CTT', 'CTT01': nr_lines})

getcountsum

Signature: getcountsum(*mpath), with the field to add up marked None in the last dict. Returns: the sum as a string (for example '42.000'). Non-numeric values count as 0.

total_qty = inn.getcountsum({'BOTSID': 'ST'}, {'BOTSID': 'PO1', 'PO102': None})

Common mistake: the function changes the dicts you pass (it removes the None field); do not reuse the same dict objects after the call.

put

Signature: out.put(mpath1, mpath2, …, strip=True) or node.put(…). Returns: True if written, False if a value was None or an empty list (then nothing is written).

For each level: if a record with the same values in the fields both have already exists, it is used and the new fields are added to it; otherwise a new record is added. Values are converted with str() and stripped of spaces at both ends (strip=False keeps the spaces). A list as value is a repeating field (a list of dicts: a repeating composite).

out.put({'BOTSID': 'UNH', '0062': out.ta_info['reference'], 'S009.0065': 'INVOIC',
         'S009.0052': 'D', 'S009.0054': '96A', 'S009.0051': 'UN', 'S009.0057': 'EAN008'})
out.put({'BOTSID': 'UNH'}, {'BOTSID': 'BGM', 'C002.1001': '380', '1004': invoicenumber})
out.put({'BOTSID': 'UNH'}, {'BOTSID': 'NAD', '3035': 'SU', 'C082.3039': '5412345000013', 'C082.3055': '9'})

Common mistakes: using put for repeating records: a second put of the same record id makes a new record only when a field both have differs (here 3035); otherwise it adds to the first record. For lines use putloop. A None anywhere in the mpath means nothing is written, also not the other fields: use that on purpose for optional values, but do not put mandatory and optional fields in one call.

putraw

Signature: putraw(*mpath). As put, but values are stored as given: no str(), no stripping (for example a boolean or number for json). new in 4.0

putloop

Signature: putloop(*mpath). Returns: the node of a new record at the end of the mpath (the levels above are reused or made). Then use put on that node, starting with its own record. Returns False if a value in the mpath is None.

for po1 in inn.getloop({'BOTSID': 'ST'}, {'BOTSID': 'PO1'}):
    lin = out.putloop({'BOTSID': 'UNH'}, {'BOTSID': 'LIN'})
    lin.put({'BOTSID': 'LIN', '1082': po1.get({'BOTSID': 'PO1', 'PO101': None})})
    lin.put({'BOTSID': 'LIN'}, {'BOTSID': 'QTY', 'C186.6063': '21',
                                'C186.6060': po1.get({'BOTSID': 'PO1', 'PO102': None})})

Several messages in one output. If putloop is the first thing you do on an empty out, with one dict only, each call makes a new top record: each one is written as a separate message (or record) in the same file. Example: a csv file with one line per order line and no header record:

for po1 in inn.getloop({'BOTSID': 'ST'}, {'BOTSID': 'PO1'}):
    row = out.putloop({'BOTSID': 'LIN'})
    row.put({'BOTSID': 'LIN', 'sku': po1.get({'BOTSID': 'PO1', 'PO107': None})})

change

Signature: change(where, change). where is a tuple of dicts (an mpath, values as strings), change a dict of fields. Returns: True if a record was found and changed. Only the first match is changed. A value None removes the field. BOTSID cannot be changed.

inn.change(where=({'BOTSID': 'UNH'}, {'BOTSID': 'NAD', '3035': 'BY'}),
           change={'C082.3039': '5412345000013', 'C082.3055': None})

Common mistake: passing the mpath as separate arguments (change({'BOTSID':'UNH'}, {…})) instead of a tuple.

delete

Signature: delete(*mpath), at least two dicts (the root cannot be deleted). Returns: True if a record was removed. The record and all records below it are removed. Only the first match.

while inn.delete({'BOTSID': 'UNH'}, {'BOTSID': 'FTX', '4451': 'ZZZ'}):
    pass   # remove all FTX+ZZZ

sort

Signature: sort(*mpath, **options). The last dict names the field to sort on (exactly one None); the dicts before it name the record whose children are sorted. Options:

  • sortfrom=(…) and compare=(…): give the two parts separately; compare can be more than one level, to sort on a field of a child record. new in 4.0
  • reverse=True: largest first.
  • sort_decimal=True: compare as numbers ('10' after '9').
  • sort_if_none='…': the value to use for records without the field; by default they come first (as in Bots 3).
inn.sort({'BOTSID': 'UNH'}, {'BOTSID': 'LIN', '1082': None}, sort_decimal=True)
inn.sort(sortfrom=({'BOTSID': 'UNH'},),
         compare=({'BOTSID': 'LIN'}, {'BOTSID': 'PIA', 'C212.7143': 'SA', 'C212.7140': None}))

enhancedget

Signature: enhancedget(mpaths). The argument is a dict (one level), a tuple of dicts (an mpath), a list (each member is fetched and the results are joined), a function (called as function(thisnode=node)), or a string (returned as it is). Bots uses it for QUERIES, SUBTRANSLATION and nextmessageblock in grammars; in a mapping it is rarely needed.

display, displayqueries, copynode

inn.root.display() writes every record of the tree to the log (level INFO), indented by level. inn.root.displayqueries() writes the QUERIES values per node. node.copynode() returns an independent copy of the node and everything below it.

ccode, reverse_ccode, getcodeset

Signature: transform.ccode(ccodeid, leftcode, field='rightcode', safe=False). Looks in the code list (Configuration → User Codes list) of type ccodeid for the entry with leftcode, and returns its field: rightcode, attr1 … attr8. If not found: safe=False raises CodeConversionError, safe=True returns leftcode unchanged, safe=None returns None.

reverse_ccode(ccodeid, rightcode, field='leftcode', safe=False) searches on rightcode. getcodeset(ccodeid, leftcode, field='rightcode') returns a list of all matching values (in the order they were entered).

unit = transform.ccode('unit_x12_to_edifact', po1.get({'BOTSID': 'PO1', 'PO103': None}))   # 'EA' -> 'PCE'
desc = transform.ccode('unit_x12_to_edifact', 'EA', field='attr1', safe=True)
x12unit = transform.reverse_ccode('unit_x12_to_edifact', 'PCE')                              # 'PCE' -> 'EA'

Common mistakes: the code type must exist under User Code types; codes are compared exactly (case and spaces matter); passing None as code raises Value "None" not in code-conversion.

partnerlookup

Signature: transform.partnerlookup(value, field, search_field='idpartner', safe=False). Finds the partner whose search_field equals value and returns its field: any field of the partner, such as name, mail, attr1 … attr5, address1, city, countrycode. A partner whose field is empty counts as not found. safe as for ccode. The Bots 3 name of the third argument, field_where_value_is_searched, also works.

erp_customer = transform.partnerlookup(inn.ta_info['frompartner'], 'attr1')
partner_id = transform.partnerlookup('5412345000099', 'idpartner', search_field='attr2', safe=None)

Common mistake: searching on a field other than idpartner that is not unique: the first partner found is used.

unique, unique_runcounter, checkunique

transform.unique(domein, updatewith=None) returns the next number of the counter domein (max 128 characters) as a string. A new counter starts at 1. With updatewith=n it returns the current number and sets the counter to n. Two engines can never get the same number. Counters are listed and can be changed in SysTasks → View/edit counters (see Counters). In an acceptance test run, unique uses a counter per run.

transform.unique_runcounter(domein, updatewith=None) is a counter in memory that starts again at 1 in each run.

transform.checkunique(domein, receivednumber) returns True if receivednumber is the next number of the counter (and moves the counter), else False (and leaves it). receivednumber must be an integer.

seq = int(inn.get({'BOTSID': 'HDR', 'sequence': None}))
if not transform.checkunique('erp_sequence', seq):
    raise transform.BotsError('Sequence number %(seq)s is out of order.', {'seq': seq})

inn2out

transform.inn2out(inn, out) sets out.root to a copy of the incoming tree. Use it when input and output have the same or almost the same structure; change the copy afterwards with out.change, out.delete and out.put.

def main(inn, out):
    transform.inn2out(inn, out)
    out.change(where=({'BOTSID': 'UNH'}, {'BOTSID': 'NAD', '3035': 'BY'}),
               change={'C082.3039': '5412345000013'})

useoneof, truncate, concat, dropdiacritics, chunk

  • useoneof(*args): the first argument that is not empty, else None. transform.useoneof(buyer_article, vendor_article, 'UNKNOWN')
  • truncate(maxpos, value): value[:maxpos]; None stays None. Mind the order: length first.
  • concat(*args, sep=''): joins the non-empty arguments with sep; None if nothing is left. transform.concat(street, number, sep=' ')
  • dropdiacritics(content, charset='ascii'): every character that does not fit in charset is replaced by the character without accent, or dropped. One character in gives at most one character out, so lengths do not grow.
  • chunk(sequence, size): a generator of parts: list(transform.chunk('a long free text', 5)) gives ['a lon', 'g fre', 'e tex', 't']. Useful for FTX lines of fixed length.

dateformat, datemask, strftime

  • dateformat(date): '102' for 8 characters (CCYYMMDD), '203' for 12 (CCYYMMDDHHMM), '718' for 16 (a period of two dates); None for an empty date; any other length raises No valid edifact date format for "…".
  • datemask(value, frommask, tomask): each character of frommask labels the character at the same position in value; tomask is built from these labels, other characters are copied. transform.datemask('12/31/2026', 'MM/DD/CCYY', 'CCYYMMDD') gives '20261231'. An empty value is returned unchanged.
  • strftime(format): the current date and time, as Python's strftime. In an acceptance test run it always gives 2013-01-23 01:23:45, so test output does not change.
orderdate = inn.get({'BOTSID': 'ST'}, {'BOTSID': 'BEG', 'BEG05': None})      # '20261231'
out.put({'BOTSID': 'UNH'}, {'BOTSID': 'DTM', 'C507.2005': '137', 'C507.2380': orderdate,
                            'C507.2379': transform.dateformat(orderdate)})

calceancheckdigit, checkean, addeancheckdigit

calceancheckdigit(ean) returns the check digit (a string) for a GTIN/GLN without its check digit. checkean(ean) returns True if the last digit is right. addeancheckdigit(ean) returns the code with the check digit added. The code must be a string of digits, else EanError (GTIN "…" should be string with only numericals.).

sendbotsemail

transform.sendbotsemail(partner, subject, reporttext) sends a plain text mail to the mail and CC addresses of the partner, with the mail server of settings.py (EMAIL_HOST, …) and SERVER_EMAIL as sender. Returns: the result of Django's send_mail (1 when sent), False on an error (logged as warning), None if the partner is unknown or has no mail address. It does not raise, so the translation continues.

Exceptions you can raise

  • transform.BotsError(text, dict): a clear error for this message. The text uses %(name)s placeholders filled from the dict.
  • transform.KillWholeFileException(text): this message and all other messages of the file fail; nothing of the file is output.
  • transform.ParsePassthroughException(text): stop translating; the incoming file is passed on unchanged, as in a "parse and passthrough" route.

Mapping recipes

Ready-to-use pieces of mapping code for the jobs that come back in almost every mapping. Copy a recipe into your main function and change the record and field names to those of your grammars.

In plain words

These are worked examples. Each one solves one small problem, such as "add up the line amounts" or "send nothing for test orders". Combine them to build a complete mapping.

How it works

All recipes assume these imports at the top of the mapping file and the grammars used in this manual: X12 850004010 (root ST, lines PO1), EDIFACT ORDERSD96AUNEAN008 / INVOICD96AUNEAN008 (root UNH), and a csv grammar orders_erp with a header record HDR and line records LIN below it.

import decimal
from bots import botsglobal
from bots import transform

Field names in the examples are those of the standard grammars; check them in your own grammar with the "view grammar" link in Configuration → Translations.

How to use a recipe

  1. Pick the recipe from the list in the reference below.
  2. Copy it into the main(inn, out) of your mapping, below the part that writes the header.
  3. Rename records and fields to those of your incoming and outgoing grammars.
  4. Set up what the recipe needs: a code list, a partner field, a second translation rule (each recipe says so).
  5. Test with a real file and check the result in Outgoing.

8. One input, several output messages

Same file, several messages: start out with putloop of one record (see putloop); each top record is written as its own message in the same file.

Several files: return an alt. Each time main returns a string, Bots writes the current out and runs the translation again for the same incoming message, with inn.ta_info['alt'] set to that string and a new empty out. If no translation rule has that exact alt, the rule with an empty alt (this same mapping) is used. Example: one csv file per ship-to address of an order.

def main(inn, out):
    shiptos = sorted(set(sdq for sdq in
                     (n.get({'BOTSID': 'SDQ', 'SDQ03': None})
                      for n in inn.getloop({'BOTSID': 'ST'}, {'BOTSID': 'PO1'}, {'BOTSID': 'SDQ'}))
                     if sdq))
    alt = inn.ta_info['alt']
    index = int(alt.split('_')[1]) if alt.startswith('shipto_') else 0
    write_order_for(inn, out, shiptos[index])          # your own function that fills out
    if index + 1 < len(shiptos):
        return 'shipto_%s' % (index + 1)                # next file
    return None                                          # done

Each returned value differs, so Bots does not see an endless loop. If you must return the same value again and again, return {'type': 'no_check_on_infinite_loop', 'alt': value} and make sure the chain ends.

Several messages in the input: that is done by the incoming grammar (nextmessage or nextmessageblock): main is then called once per message.

User scripts

User scripts are Python files in the folder usersys of your environment. Bots calls functions in them at fixed moments, so you can change what Bots does without changing Bots itself. This page gives the overview: which kinds exist, where each goes, and the rules they all follow.

In plain words

Bots has "hooks": fixed points where it looks for a Python file with a certain name. If the file is there and has a function with a certain name, Bots runs it. A mapping is one kind of hook; others let you change how files are sent, received, enveloped, or what a route does.

How it works

  1. At start, Bots imports the usersys folder of the environment (set in bots.ini, [directories] usersys; see Environments) as a Python package.
  2. At each hook, Bots builds a module name from the kind of script and the name of the thing it works on, for example routescripts.orders_in for route orders_in, and imports it with botslib.botsimport.
  3. If the file does not exist, Bots goes on without it; this is not an error. Bots remembers this for the rest of the run and does not look again. If the file exists but has an error (a syntax error, or an import that fails inside it), the step fails with Error in import of module "…".
  4. If the module has the function Bots is looking for, Bots calls it with keyword arguments (botslib.runscript). The names of the parameters of your function must be exactly the names Bots passes; or end your function with **kwargs. A function that is missing is skipped.
  5. An exception in your function is turned into ScriptError: Userscript "…": "…". Where that error ends up depends on the hook (a message, a file, or a process error of the run); each page says so.

A module is imported once per run of the engine. Variables at module level keep their value during the run, but not between runs; use the database (transform.persist_*, transform.unique) for that.

How to add a user script

  1. Find the folder and file name in the reference table below. The file name is the id of the channel, route, envelope or partner, exactly as in the configuration (case matters on Linux), plus .py.
  2. Write the function with the exact name and parameter names of the hook.
  3. Check it. Run bots-checkusersys -c<config directory>: it compiles every Python file in usersys and imports every script, and lists errors.
  4. Check that Bots sees it. In Configuration → Routes and Configuration → Channels the column User script shows a View link when a route script or communication script exists; it opens the source.
  5. Run and look at the result in the reports; errors of scripts that are not tied to a file show under All runs → Process Errors.

Communication scripts

A communication script changes how one channel sends or receives files: the outgoing file name, the subject of a mail, the SSH key of an SFTP server, or the whole way of communicating. For channel types communicationscript and db the script is the communication.

In plain words

The channel screen covers the usual cases. When a partner wants something special, such as a file name built from the order number, or a key file that is stored somewhere else, you write a few lines of Python with the name of the channel. Bots then asks your script at that moment.

How it works

When a channel runs, Bots imports usersys/communicationscripts/<channel id>.py if it exists. Then:

  1. If the script contains a class with the name of the channel type (for example sftp), Bots uses that class for the channel instead of its own. You subclass the class of Bots and change only the methods you need. (The old name UserCommunicationClass is still accepted.)
  2. Otherwise Bots uses its own class, and calls the functions of the script at fixed moments (the hooks below), if they exist.

Every function is called with keyword arguments; use the parameter names shown in the reference. channeldict is a dict with all fields of the channel: idchannel, inorout, type, host, port, username, secret, path, filename, parameters, archivepath, keyfile, certfile, cafile, verify_cert, remove, testpath, charset, debug and the others. ta is the database record of the file (its fields as attributes: ta.idta, ta.frompartner, ta.topartner, ta.botskey, ta.editype, ta.messagetype, ta.filename, …).

An error in a hook during sending marks that file as failed (it can be resent); an error during receiving or connecting shows as a process error of the run.

How to build the outgoing file name in a script

Often the Filename field of the channel is enough: {botskey}_{unique}.edi, {topartner}/{infile:name}.txt, {datetime:%Y%m%d}_{unique}.xml (see File channels). Use a script when you need more.

  1. Create the file usersys/communicationscripts/partnera_sftp_out.py (the id of the outgoing channel).
  2. Add the function: 
    def filename(channeldict, filename, ta):
    """filename: the name made from the Filename field of the channel; ta: the file to send."""
    if ta.messagetype.startswith('INVOIC'):
        return 'INV_%s_%s.edi' % (ta.topartner, ta.botskey or ta.idta)
    return filename
  3. Run the route and check the name in Outgoing: the column with the external file name.

How to give an SFTP channel its host key and private key

  1. Create usersys/communicationscripts/partnera_sftp_out.py.
  2. Add the hooks: 
    import base64

    """(key file, key type, passphrase); key type may be None: Bots tries all types."""
    return ('/srv/edi/keys/partnera_id_ed25519', 'ED25519', 'secret-example')
  3. Run the channel. A wrong host key stops the connection with an SSH error; a wrong passphrase gives sftp: can not read private key ….

Without a script you can also fill Private key file in the channel; the Password is then the passphrase of the key. The host key is only checked when a hostkey hook supplies it.

How to write a channel of type communicationscript

Use this type to call your own program, or to fetch or deliver files in a way Bots does not know.

  1. Make the channel in Configuration → Channels → Add with Type communicationscript, and fill Path and Filename (for example C:\edi\in and *.xml).
  2. Write connect (required): for an incoming channel it puts the files in Path, or opens a connection. For example: 
    import subprocess


def connect(channeldict):
    subprocess.run(['/srv/edi/bin/export_orders', channeldict['path']], check=True, timeout=300)
  3. Choose how files are passed: without a function main, Bots takes every file in Path that matches Filename after connect. With a generator main(channeldict) that yields full file names, Bots takes those files one by one.
  4. For an outgoing channel, Bots writes each file to Path with the name from Filename, then calls main(channeldict, filename, ta) for it if it exists; otherwise do the work for all files in disconnect(channeldict).
  5. Tick Remove if Bots must delete the files afterwards.

How to write a database channel script

For channel type db, set the Database field of the channel (MySQL/MariaDB, PostgreSQL, SQLite, SQL Server) with host, port, username, password and the database in Path; Bots then makes the connection, and the script only needs incommunicate or outcommunicate. See Database channels. new in 4.0

# usersys/communicationscripts/erp_db_in.py
def incommunicate(channeldict, dbconnection):
    cursor = dbconnection.cursor()
    cursor.execute("SELECT * FROM orders WHERE status = %(status)s", {'status': 'ready'})
    rows = cursor.fetchall()
    cursor.execute("UPDATE orders SET status = 'sent' WHERE status = 'ready'")
    return [rows]            # one message with all rows; a list with one item per message

Bots commits when the function ends without error and rolls back when it raises; do not commit yourself. What incommunicate returns becomes the incoming data: None or empty: nothing; a list or tuple: one incoming file per element; anything else: one file. The mapping (editype db) gets it as inn.root. For outgoing, the mapping sets out.root and outcommunicate(channeldict, dbconnection, db_object) gets that object. A Bots 3 script with its own connect(channeldict) (returning the connection) and disconnect(channeldict, dbconnection) keeps working.

Route scripts

A route script runs your own Python code at fixed points of a route: before or after receiving, translating, merging and sending. It can also replace the route completely. A second kind of script, botsengine.py, runs before and after a whole run of the engine.

In plain words

A route is a fixed chain of steps. A route script lets you slip in an extra step, such as "after receiving, mark all files from this folder as coming from PartnerA" or "before sending, copy the files to a backup server". You only write the steps you need.

How it works

For every route-part (every line of the route, in the order of Sequence) Bots imports usersys/routescripts/<route id>.py if it exists, and calls these functions if they are in it. Each is called as function(routedict=routedict).

  1. If the script has main, Bots calls only main for the route-part and does nothing else: the script is the route-part.
  2. Otherwise start is called, then the normal steps run with the hooks around them. A hook of a step is only called when that step runs: receive hooks only when the route-part has an incoming channel; translate and merge hooks only when Translate is "Translate" or "Parse & Pass-through"; send hooks only when there is an outgoing channel, it is not deferred, and there are files to send.
  3. At the end of the route-part end is called.

The hooks run in every kind of run (new, resend, rereceive, automaticretrycommunication, crashrecovery); routedict['command'] tells you which. If a hook raises an error, the rest of that route-part is skipped and the error shows under All runs → Process Errors; the next route-part and the next routes still run.

How to set the partner of received files

Example: files in C:\edi\in carry no partner id in their content, but each file name starts with the partner id (PARTNERA_order_123.csv).

  1. Create usersys/routescripts/orders_in.py (the route id).
  2. Add the hook postincommunication; it runs right after the files are received and the route has given them its editype and messagetype: 
    import os
from bots import botsglobal, botslib, transform


def postincommunication(routedict):
    for row in botslib.query(
            """SELECT idta, filename FROM ta
               WHERE idta > %(rootidta)s AND status = %(status)s AND statust = %(statust)s
               AND idroute = %(idroute)s AND fromchannel = %(fromchannel)s""",
            {'rootidta': botsglobal.currentrun.get_minta4query_routepart(),
             'status': transform.FILEIN, 'statust': transform.OK,
             'idroute': routedict['idroute'], 'fromchannel': routedict['fromchannel']}):
        external = botslib.trace_origin(botslib.OldTransaction(row['idta']), {'status': transform.EXTERNIN})
        name = os.path.basename(external[0].filename) if external else ''
        partner = name.split('_')[0].upper()
        botslib.OldTransaction(row['idta']).update(frompartner=partner)
  3. Run the route. In Incoming the column of the from-partner now shows PARTNERA; the translation can select a partner-specific mapping.

Envelope scripts

An envelope script changes the envelope that Bots puts around outgoing messages: the UNB/UNZ of EDIFACT, the ISA/GS/GE/IEA of X12, the STX/END of tradacoms, or the header line of a csv file. Use it for partner-specific envelope values that the grammar and partner syntax cannot give, or to write an envelope Bots does not know.

In plain words

After translating, Bots puts the messages for one partner together in one file and adds an "envelope": a first and last line with sender, receiver, date and a control number. An envelope script lets you fill in or change those lines yourself.

How it works

  1. The outgoing grammar (or the mapping) decides the envelope with syntax envelope: 'edifact', 'x12', 'tradacoms', 'templatehtml', 'csvheader', 'json', or empty for no envelope. See Envelopes.
  2. When enveloping, Bots imports usersys/envelopescripts/<editype>/<envelope>.py, for example envelopescripts/edifact/edifact.py. With an empty envelope no script is used.
  3. If that file has a class with the name of the envelope, Bots uses it instead of its own envelope class.
  4. Otherwise Bots runs its own envelope and calls two functions of the file if they exist:
    • ta_infocontent(ta_info): early, when the values for the envelope are collected. Change values in the dict ta_info.
    • envelopecontent(ta_info, out): for EDIFACT, X12 and tradacoms, after the envelope records are built and before they are checked and written. Change the records with out.put or out.change.

Where an envelope value comes from, highest priority first (EDIFACT UNB and X12 ISA/GS):

  1. A value the mapping set in out.envelope_content (see recipe 17).
  2. A value in ta_info: from ta_infocontent, from the partner syntax (usersys/partners/<editype>/<partner>.py), or from the grammar syntax (for example UNB.0029, ISA05).
  3. The partner ids of the messages (from-partner and to-partner), converted according to syntax IDmode.

An error in an envelope script marks the merged file as failed (status error in Outgoing); the messages inside it are not sent.

How to set partner-specific UNB values

Example: PartnerA wants an application reference in UNB and its own GLN as receiver, while the partner id in Bots stays PARTNERA.

  1. Create usersys/envelopescripts/edifact/edifact.py.
  2. Add ta_infocontent: 
    def ta_infocontent(ta_info):
    if ta_info['topartner'] == 'PARTNERA':
        ta_info['S003.0010'] = '5400000000003'      # receiver id in UNB
        ta_info['topartner_qualifier'] = '14'        # receiver qualifier
        ta_info['UNB.0026'] = ta_info['messagetype'][:6]   # application reference, eg 'INVOIC'
  3. Run a route that sends to PartnerA and open the file in Outgoing: the UNB contains the new values.
Tip

Values that are always the same for a partner can also go in a partner syntax file without any code: usersys/partners/edifact/PARTNERA.py with syntax = {'UNB.0026': 'INVOIC', 'forceUNA': True}. Use the envelope script when the value depends on something (message type, test indicator).

How to change an envelope record before it is written

  1. Create usersys/envelopescripts/x12/x12.py.
  2. Add envelopecontent: 
    def envelopecontent(ta_info, out):
    """PartnerB wants ISA14 = 0 (no TA1) and our DUNS in GS02."""

        out.change(where=({'BOTSID': 'ISA'}, {'BOTSID': 'GS'}), change={'GS02': '123456789'})
  3. Run and check the ISA and GS segments in the outgoing file.

Preprocessing

Preprocessing changes received files before they are translated: split a file with several interchanges, unzip, or turn a PDF into csv. Some preprocessing Bots does by itself (mailbag, unzip); other functions you call from a route script. You can also write your own.

In plain words

Sometimes a received file is not ready to be read: it is zipped, it holds orders of several partners glued together, or it is a PDF. Preprocessing is the step that unpacks or cleans the file first, so the translation gets something it can read.

How it works

  1. The incoming channel receives the files. They get status "received" (FILEIN) and the route sets their editype and messagetype.
  2. Bots runs a preprocessing function on every received file of this route-part and incoming channel. The function reads the file and writes one or more new files; each new file gets a new record with status FILEIN. The original record is set to done, so only the new files are translated.
  3. If the function fails for a file, that file gets status error with the error text, and no new files are kept for it. Other files go on.

Order in a route-part: receive → postincommunication of the route script → unzip (if set in the route) → mailbag (for EDIFACT, X12, tradacoms and mailbag) → translate. Before sending: zip (if set in the route) → preoutcommunication → send.

How to receive files with several interchanges or mixed types

  1. Set the route. In Configuration → Routes, set Fromeditype to edifact, x12 or tradacoms (mailbag runs automatically and splits the file per interchange), or to mailbag when one channel receives a mix of EDIFACT, X12, tradacoms and xml.
  2. Set the messagetype. With Frommessagetype edifact/x12/mailbag the exact messagetype is found later from the content. A specific messagetype (for example ORDERSD96AUNEAN008) is kept.
  3. Run. In Incoming each interchange of the file shows as a separate file with the right editype.

How to unzip received files

  1. Open the route and set Incoming zip-file handling to "Always unzip file" (a file that is not a zip is an error) or "If zip-file: unzip" (other files pass unchanged).
  2. Run. Every file in the zip becomes a received file; folders in the zip are skipped.
  3. For a zip with a password, leave the route field empty and call the function from the route script: 
    # usersys/routescripts/orders_in.py
from bots import preprocess


def postincommunication(routedict):
    preprocess.preprocess(routedict=routedict, function=preprocess.botsunzip,
                          password=b'secret-example', pass_non_zip=True)
    The password must be bytes (b'…').

How to read a PDF as csv

  1. Install the library: pip install "bots-ediint[pdf]" (installs pdfminer.six).
  2. Make a csv grammar for the result. Each row is: page number, line number, then the text fields of that line, separated by ,. Set the route Fromeditype to csv and Frommessagetype to that grammar.
  3. Call extractpdf in the route script: 
    from bots import preprocess


def postincommunication(routedict):
    preprocess.preprocess(routedict=routedict, function=preprocess.extractpdf,
                          x_group=10, y_group=5, field_sep=';', charset='utf-8')
  4. Run and open the result in Incoming to see how the PDF was split into fields; adjust x_group (how close text must be to count as one field) and y_group (how close lines must be to count as one line).
Watch out

A PDF that contains only images (a scan) has no text: extractpdf fails with PDF text extraction failed, it may contain just image(s)?. Excel files do not need preprocessing: use editype excel (see Other editypes).

How to write your own preprocessing function

  1. Write the function in the route script. It gets ta_from (the received file; ta_from.filename is its internal name), endstatus, routedict and your own keyword arguments. It must make a new record for each output file and fill it: 
    from bots import botslib, preprocess, transform


def strip_bom(ta_from, endstatus, **kwargs):
    """Remove a UTF-8 byte order mark at the start of the file."""
    content = botslib.readdata_bin(ta_from.filename)
    if content.startswith(b'\xef\xbb\xbf'):
        content = content[3:]
    ta_to = ta_from.copyta(status=endstatus)          # new record, same editype/partners
    tofilename = str(ta_to.idta)
    with botslib.opendata_bin(tofilename, 'wb') as tofile:
        tofile.write(content)
    ta_to.update(statust=transform.OK, filename=tofilename, filesize=len(content))


def postincommunication(routedict):
    preprocess.preprocess(routedict=routedict, function=strip_bom)
  2. Raise an exception for a file that cannot be handled; Bots marks that file as error.
  3. Run and check in Incoming that each received file has a child file.

To change the editype or messagetype of the new file, pass them in update: ta_to.update(statust=transform.OK, filename=tofilename, editype='xml', messagetype='orders_xml').
